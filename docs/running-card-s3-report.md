### 2-1. 명판 맵 — `Relief.plate(figure)` (`src/components/running-card/medal/medal3d-relief.js`)

- `plate(figure = null, W, Hh, size)`. 인물(`{ name, house }`)이 없으면 S2와 같은 `지난 28일` 명판이다(같은 코드 경로. 01–07 스크린샷은 눈금자 착지가 같은 실행에서 차이 0, 5-2절).
- 인물이 있으면 왼쪽에 가문 기호, 세로 구분선, 오른쪽에 인물명(760 굵기)과 그 아래 `{가문} 가문`(550)을 새긴다. `지난 28일`은 명판에서 뺐다(공유 머리글·끈에 있다).
  - 배치(명판 단위, 가운데 원점): 기호 중심 x −0.64·반폭 0.265, 구분선 x −0.27, 글자 열 중심 x 0.37·최대 폭 1.10(넘치면 줄인다).
  - 390×844 완료 화면에서 1단위 ≈ 47.4px이다. 기호 높이 ≈ 25px, 법랑 면 ≈ 103×34px, 인물명 ≈ 12px, 가문명 ≈ 6.4px다(계산값, `completeRig` 식).
- 기호 12개(`SIGNS`)는 Canvas 경로로 그리고 동전과 같은 `mask → bevel → level` 파이프라인에 넣었다. 흰색 = 돋운 금속, `carve` = 법랑까지 깎기다. 기호는 bevel 반경 2, 글자는 1(기존 명판 글자와 같음)이다. 광택·거칠기 규칙은 기존 명판 `maps()` 인자를 그대로 쓴다.

### 2-2. 각인 모션·제목 전환 (`medal3d-flow.js`)

- 07 다음 → `judge()`가 `{ analysis, title }`을 돌려준다(`running-card-medal.tsx`, 칭호는 `presentation.ts`).
- `finish()` → `engrave()`:
  1. 제목은 `지난 28일의 메달` 그대로 두고, 그 아래 줄(`#complete-epithet`, `role=status`)에 `28일의 기록을 신화로 번역하고 있어요`를 한 번 띄운다.
  2. 명판 맵을 우선순위 0으로 요청한다(워커).
  3. 맵이 오고 메달 전체가 화면에 들어오면(`go()`가 돌려주는 시각) 새 명판을 미리보기 강도(`PREVIEW` .55)로 바꿔 끼운다.
  4. `DROP`(180ms) 뒤 0.26초 동안 100%로 올라가고, 같은 순간 메달이 한 번 눌린다(`recoil` 280ms). 동전 각인 `strikeCoin`·다시 새김 `restrike`와 같은 값·같은 곡선이다. 새 모션 문법은 없다. 반짝이·광선 없음.
  5. 다 올라가면 제목 → `{인물명}`, 칭호 줄 → `{칭호}`(입력 단계 머리글과 같은 320ms 떠오름). `#medal-status`에 `명판을 새겼어요. {가문} 가문, {인물명}.`, 메달 설명(aria-label)에 `가운데 명판에는 {가문} 가문 기호와 {인물명}.`을 붙인다.
- 명판 재질: 법랑 재질에 동전과 같은 `uStrike` 패치를 붙였다(`polished(…, { strike: uPlate, ground: 0 })`). 동전은 미리보기에서 은빛 새틴(.62)으로 흐려지고, 명판 글자는 법랑(0)으로 가라앉는다. 법선 세기도 같은 값으로 오른다.
- 모션 줄이기·느린 렌더러(SwiftShader): 맵이 오는 즉시 100%로 바꾸고 제목도 바로 바꾼다(카메라 즉시 전환은 기존 규칙).
- WebGL 없음: 평면 대체 그림의 명판 자리에 그 명판 맵의 `preview`를 그린다(즉시).
- 완료 화면을 각인 도중에 떠나면(다시 다듬기) 남은 각인을 즉시 끝낸다(`settlePlate`). 기록을 고치는 동안 명판은 마지막 인물을 그대로 지닌다. 다시 07 다음 → 인물이 바뀌었으면 다시 새긴다.
- 공유 이미지: 메달 그림은 3D 장면(또는 평면 그림)을 그대로 찍으므로 새 명판이 그대로 들어간다. `facesReady()`가 각인 중인 명판 맵도 기다린다. 공유 레이아웃·문구는 손대지 않았다(S4).
- 임시 줄 `판정: {인물}`과 그 `<p class="completion-note">`·CSS를 없앴다. 그 자리 높이(약 23px)는 제목 아래 칭호 줄(20px + 3px)이 가져갔다. 완료 그림 상자 크기는 거의 같다(390×844: 377.5px, S2 376.9px).

## 6. S4로 넘길 것

1. **결과 카드**
   - 판정은 흐름 안 `analysis`와 `epithet`(칭호)에 있다.
   - 신탁·근거·강점·맹점·다음 행동은 `presentation.ts`의 `CharacterPresentation` 타입에 필드를 더해 가져온다. 원본은 `aa794de`이고, 이번에 칭호를 옮길 때 글자 단위로 대조한 스크립트 방식을 그대로 쓰면 된다.
2. **칭호 문구 검수**: 3절의 걸림 4건(헤스티아·디오니소스·프시케·오르페우스)과 경계 7건. 이번에는 바꾸지 않았다.
3. **공유 이미지(D6)**
   - 메달 그림에는 명판이 이미 들어간다.
   - 1장에 인물명·칭호·신탁을 캔버스로 그리면, 그 글자의 출처 파일(`presentation.ts`)을 `scripts/build-medal-fonts.js`의 `SOURCES`에 넣고 다시 돌려야 한다. 지금 칭호는 화면 글꼴로만 그린다.
   - WebGL 없음 공유 이미지는 화면 배치를 그대로 축소해서 메달이 작다. 공유용 구도로 따로 그리는 편이 낫다.
4. **완료 화면 배치**
   - 제목 아래 칭호 줄(`#complete-epithet`)은 `role=status`이고, 대기 문구도 같은 줄에 뜬다. 결과 카드가 생기면 칭호를 표지 쪽으로 옮길지 정한다.
   - 줄을 옮기면 대기 문구 자리도 함께 옮긴다.
5. **각인 알림 문장**: 가문의 신이면 `명판을 새겼어요. 아테나 가문, 아테나.`처럼 이름이 겹친다. 문구 검수 때 함께 본다.
6. **4절 약한 기호 3개와 `{가문} 가문` 1배 판독 불가**는 운영자 판단 대기다. 인물 속성 기호 36개는 S7이다.
7. **같은 인물 재판정 때 대기 문구 생략**(1절)이 괜찮은지 운영자에게 확인한다.
8. 탐색 계산(exploratory): 격자 110,880건에서 인물 아레스는 0건이다. 아레스의 칭호는 지금 엔진으로는 화면에 나오지 않는다(설계 §6-5와 같은 결과). 아레스 가문 기호는 헥토르·펜테실레이아로 나온다.
9. S2에서 넘어온 것 중 이번에 손대지 않은 것: 동전 05 쉐브론 6자리·06 목표 기록 시트 디자인 승인, 공유 시트의 `#share-sample` 문구와 요약의 `예시` 꼬리표(도달하지 않는 코드).
