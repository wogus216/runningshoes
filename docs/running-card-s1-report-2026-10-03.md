## 4. 어댑터 — `src/lib/runner-analysis/from-flow-input.ts`

```ts
snapshotFromFlowInput({ values, origins, raceGoal }: FlowInput): FlowSnapshotResult
// ok: true → snapshot / ok: false → reason 'sample' | 'invalid', fields
```

- `values`·`origins`는 `medal3d-flow.js` 객체를 그대로 넘긴다. `liveRec()`(빈칸을 메움)는 쓰지 않는다.
- 무효를 먼저 검사하고, 그다음 예시를 검사한다. 무효 규칙은 입력 흐름의 `validation()`과 같다.
- D1: 네 기록 중 `sample`이 남아 있으면 `reason: 'sample'`이다. `confirmed`면 통과한다.
- 요일은 `(i + 1) % 7` 후 중복 제거·정렬한다. 빈 배열이면 `usualWeekdays`를 넣지 않는다.
- `raceGoal`은 목표가 `race`·`record`일 때만 넘기고, 유한 양수가 아니면 `invalid`다.

## 6. S2(3D 이식)로 넘길 변경

1. **05 강한 훈련 칩**: `0·1·2·3·4·5·6회 이상`(value 6)의 7칸으로 바꾼다. 횟수보다 큰 칩은 비활성이다. 동전 05 쉐브론은 6자리로 늘린다.
2. **07 요일 문구**: `선택 항목이에요. 주로 달리는 요일을 고르면 회복 여유를 더 정확히 계산해요.`로 바꾼다. 고른 요일 수가 `round(횟수 ÷ 4)`를 넘으면 안내 한 줄을 띄운다(진행은 막지 않음). `요일은 건너뛸게요` 버튼은 그대로 둔다.
3. **D1 확인 블록**: `예시값 그대로 볼게요`를 `이 숫자가 내 기록이 맞아요`로 바꾼다.
   - 누르면 남은 예시 칸이 `confirmed`가 된다.
   - `sample`인 동안에는 판정·명판 각인·공유를 열지 않는다.
4. **목표 거리·기록(D2)**: 06에서 `대회`·`기록`을 고르면 선택 입력을 펼친다. 값은 `raceGoal: { distanceKm, targetTimeMinutes }`이다.
5. **연결**: 07 다음에 `snapshotFromFlowInput()`을 부른다.
   - `invalid`면 `fields[0]` 단계로 보낸다.
   - `sample`이면 확인 블록을 띄운다.
   - `ok`이면 `analyzeRunner()`를 부른다.
   - 완료 문구 `입력 시연이라 분석은 아직 연결하지 않았어요`도 바꾼다.
