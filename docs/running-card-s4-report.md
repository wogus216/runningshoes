### 2-1. `explain.ts` (스펙 404-436행)

- **대표 수치**: 공개 3축 중 '판정에 가장 크게 기여한 축'. 세 축의 가중치가 같으므로(각 18%) 기여 = 인물 목표와의 유사도다. 그래서 '인물 목표와 가장 가까운 축'을 고른다. 같으면 지구력 → 훈련 자극 → 회복 여유 순이다.
  - 프로토타입은 '가장 큰 점수'였다(설계 §3-2). 스펙으로 맞췄다.
  - 결과 예: 스펙 기준 사례 A(헤라클레스)의 대표 수치는 지구력 83이 아니라 **훈련 자극 56**이다. 헤라클레스 목표 S55와 1.4점 차이로 가장 가깝기 때문이다(E 차이 12, R 4.4). 정의대로지만, '장거리 영웅인데 대표가 훈련 자극'으로 읽힐 수 있다. 정의를 바꿀지는 운영자 판단이다(S5).
- **근거 2**: ① 여섯 특성 중 사용자 점수 60 이상이면서 인물 목표와 가장 가까운 특성의 계열. 60 이상이 없으면 문턱 없이 가장 가까운 것. ② ①과 다른 계열 중 스펙 우선순위(장거리 · 총거리 · 빈도 · 품질훈련 · 간격 · 목표)가 가장 앞선 것.
  - 계열 대응: 지구력 → 총거리, 장거리 성향 → 장거리, 품질훈련 성향 → 품질훈련, 회복 여유 → 간격, 훈련 자극 → 품질훈련(강한 훈련 0회면 장거리 — 그때 S는 최장·1회 평균에서 나온 값이다).
  - **규칙성(C)은 후보에서 뺐다.** 날짜 입력이 없어 C는 요일을 고르면 상수 75, 안 고르면 50이다(`score.ts`). 기록에서 나온 값이 아니다. 넣으면 사례 A에서 C(차이 0)가 첫 근거가 되어 스펙의 예상 근거와 어긋난다.
  - 목표 계열은 목표 기록이 있을 때만 후보다(근거에는 실제 숫자가 들어가야 한다).
  - 문장(모두 사용자 입력에서 계산): `28일 동안 150km` · `1회 평균 18.8km · 최장 30km` · `28일 동안 8회` · `10회 중 강한 훈련 2회`(6은 `6회 이상`) · `화·목·일 · 간격 2·3·2일`(월요일부터 읽음, 하나면 `화요일 · 간격 7일`, 요일 없으면 `28일에 9회 · 평균 3.1일에 한 번`) · `목표 풀코스 3시간 50분`.
  - 숫자 숨김용 문장(`hiddenText`)이 계열마다 따로 있다(3-4절).
  - 사례 A: `1회 평균 18.8km · 최장 30km` + `28일 동안 150km` = 스펙의 예상 공유 근거 두 개.

- **맹점**: 규칙 1–4를 먼저 맞는 순서로, 아니면 인물 기본 맹점. 1번 문장은 스펙 사례 A 예상 문장 그대로이고, 2–4번은 새로 썼다(3-4절).

    - 36명 각각 R 49.9에서 늘리는 말이 0이다.

    - 모든 다음 행동에 거리 숫자(`…km`)·횟수 늘리기(`회 더`·`한 번 더`·`하루 더`)가 없다. 그래서 스펙의 '주당 +1회 초과 금지'·'최장거리보다 긴 장거리 금지'도 구조적으로 지켜진다.

### 2-3. 칭호 줄·대기 문구(`#complete-epithet`, `role=status`)는 옮기지 않았다

- 판단: **완료 화면 제목 아래 그대로 둔다.** 결과 카드 표지 띠에는 칭호를 한 번 더 쓴다.
- 이유:
  1. 대기 문구 `28일의 기록을 신화로 번역하고 있어요`는 각인 1.5초 동안 눈이 있는 곳(제목 자리)에 떠야 한다. 표지 띠는 100svh 메달 아래, 화면 밖이다.
  2. 이름 → 칭호가 바뀌는 순간이 '여덟 번째 각인'의 드러남이다. 화면 밖으로 옮기면 그 순간이 안 보인다.
  3. 결과 카드는 각인이 끝난 뒤에 생긴다. `role=status`를 그 안에 두면 상태 줄과 내용이 같은 순간에 DOM에 들어간다. 그러면 스크린 리더가 첫 문구를 놓칠 수 있다(S3 1절과 같은 위험, 추정).
  4. 결과 카드를 스크롤해 읽는 사람은 제목이 화면 밖이다. 그래서 표지 띠에 인물명·칭호를 다시 둔다.

### 2-4. 공유 (D6·D11)

- **이미지 2장** — 둘 다 캔버스로 직접 그린다. DOM 캡처는 쓰지 않는다. 크기는 `medal3d-share.js` 체계 그대로 스토리 1080×1920 · 피드 1080×1350을 고른다.
  - 1장 표지: 메달(명판 각인 포함, 정면 렌더) → `{가문} 가문`(주황) → 인물명 → 칭호 → 짧은 선 → 신탁(“…”, 최대 2줄) → `allrunabout.com`. 글자를 아래에서부터 배치하고, 메달이 나머지를 쓴다. S3의 숫자 4칸·범례·`예시` 안내는 없앴다.
  - 2장 분석: `{가문} 가문` · 인물명 · 칭호 → 세 점수(막대·정수, 대표 축 주황 + `대표 수치`) → `이 인물이 된 기록` 01·02 → 강점 · 놓치기 쉬운 것 · 다음 14일 → 아래에 회복 여유 정의 줄과 주소. 피드는 내용이 다 들어갈 때까지 글자 크기를 줄인다(최소 0.6배).
  - WebGL이 없으면 평면 메달을 **공유용 구도로 따로** 그린다(`flatPaint`, 3D 공유와 같은 `fitShare` 구도). S3 인계 3의 '화면 배치를 축소해 메달이 작다'를 고쳤다.
- **기록 숫자 숨기기**(프로토타입 '공유 카드에서 기록 수치 숨기기'): 토글을 켜면 두 이미지가 바뀐다.
  - 1장: 숫자를 새긴 동전 01 총거리 · 02 횟수 · 03 페이스 · 04 최장거리 · 05 강한 훈련이 **민짜**로 그려진다. 06 목표·07 요일은 숫자가 아닌 선택이라 남긴다.
  - 2장: 근거가 숫자 없는 말(`hiddenText`)로 바뀐다.
  - 세 점수와 대표 수치는 링크에도 담기는 판정값이라 숨기지 않는다.
  - 화면 아래 안내에 무엇이 바뀌는지 그대로 적었다.
- **링크 공유**(D11, URL 방식): `?card=1.{인물}.{지구력}.{훈련 자극}.{회복 여유}.{열람 기한 36진수}`.
  - 프로토타입은 JSON이었다. 링크가 길어 메신저에 그대로 보여서 점 형식으로 줄였다. `hideNumbers`는 뺐다(링크에는 기록 숫자가 처음부터 없다).
  - 문구: `링크에는 인물과 세 점수, 열람 기한(7일)만 담기고 입력한 기록은 담기지 않아요.` — 링크 내용(`share.ts`)과 글자 그대로 맞다. '보관'·'삭제'는 쓰지 않았다. 기한은 이 페이지가 열 때 브라우저에서 판정한다. 링크를 고치면 늘어나고, 지우는 주체도 없다.
  - 열람 기한 7일은 D11 '프로토타입 그대로'라 유지했다. 링크가 7일 뒤 열리지 않아 유입이 끊기는 손해가 있다. 기한을 둘지는 S5에서 운영자에게 묻는다.
  - 폰은 `navigator.share`(제목·문장·주소), 없으면 클립보드 복사.
- **공유 링크로 들어온 화면**: 머리글 → `공유받은 러닝 카드 · 지난 28일` → 가문 → 인물명 → 칭호 → 신탁 → 세 점수(대표 축 표시) → 회복 여유 정의 줄 → **`내 메달 만들기`**(화면 아래 고정 — 8-3절 고친 것 2).
  - 판단 근거:
    1. 링크가 담은 것(인물·세 점수)과 인물에 딸린 문구(가문·칭호·신탁)만 보인다.
    2. 근거·강점·맹점·다음 행동은 보낸 사람의 기록에서 나온 것이라 링크로 되살릴 수 없다. 지어내면 거짓이다.
    3. 메달도 기록 동전이라 그리지 않는다. 메달 없이 three를 받지 않아 가볍다(공유 화면 전용 청크 1,056 + 공통 6,371바이트 gzip).
    4. 광고 슬롯 없음(스펙 186행).
  - 대표 수치는 결과 카드와 같은 규칙이다. 단, 링크의 정수 점수로 다시 고르므로 드물게 원래 결과와 갈릴 수 있다(추정: 재지 않음).
  - 기한 지난 링크 → `열람 기한이 지난 링크예요` + `내 메달 만들기`. 형식이 틀린 링크 → 그냥 입력 흐름.
  - `내 메달 만들기` → 주소에서 `card`를 지우고(`history.replaceState`) 입력 흐름을 연다.
- S3 인계 9의 도달하지 않는 예시 경로 코드를 걷었다:
  - `#share-sample` 문구
  - 요약의 `예시` 꼬리표와 `.sample-tag` CSS
  - 공유 이미지의 `예시` 칸·안내
  - 이유: 판정은 예시가 남으면 거절된다(D1). 그래서 완료 화면에 예시가 남을 수 없다.
  - 입력 중 민짜·예시 문법(`describe()`의 '각인 안 한 민짜(예시값)', 확인 블록)은 도달하므로 남겼다.

### 2-5. 목표 기록(raceGoal) 표시 — 결과 화면에만, 공유에는 넣지 않는다

- 결과 카드 `세 점수` 아래에 한 줄을 둔다. 목표 기록이 있을 때만이다: `훈련 자극에는 목표 기록(풀코스 3시간 50분)과 평균 페이스의 차이가 10% 들어 있어요.`
  - 근거: 목표 기록이 있으면 평균 페이스가 훈련 자극의 10%(목표 페이스 압력)로 들어간다. 그래서 사용자가 '왜 이 점수인지'를 알 수 있다(설계 D2). 문장은 `score.ts`의 식 그대로다.
- 목표 기록이 없을 때 '페이스는 판정에 안 썼어요'라고 쓰지 않는다. 선택값 누락을 결과에 드러내지 말라는 스펙 95행과 부딪힌다.
- 공유 이미지·링크에는 넣지 않는다. 목표 시간은 개인 목표이고 28일 기록이 아니다. 숫자 숨김과도 엮인다.

## 5. 광고 슬롯 상태

- 슬롯 ID 체계(`src/lib/constants.ts` `ADSENSE_SLOTS`): 위치마다 전용 슬롯 1개다. 형식은 `env || 하드코딩 전용 ID`다(블로그 2·신발 2·마라톤 2·홈 1).
- **러닝 카드 결과 전용 ID는 없다.** `runningCardResult: process.env.NEXT_PUBLIC_ADSENSE_SLOT_RUNNING_CARD_RESULT || ''`로 자리만 두었다.
  - 값이 비면 `AdSlot`이 `null`을 돌려 아무것도 그리지 않는다(`ad-slot.tsx:50`). 실브라우저 7회 모두 `#rc-result .ad-slot` 0개였다.
  - 다른 위치 ID를 빌려 쓰지 않았다. 위치별 보고가 섞이기 때문이다.
- 운영자 할 일: AdSense 콘솔에서 디스플레이 광고 단위 1개를 만들고, ID를 env(Cloudflare 빌드) 또는 위 폴백 자리에 넣는다. 그 뒤 결과 카드 아래·공유 위에 `format="auto"`로 뜬다.
- `AdSlot`은 그대로 썼다. 마운트 즉시 `push`하고, lazy load·IntersectionObserver는 없다. 결과 카드는 각인 뒤에 마운트되므로 그 순간 `push`한다.
- `npm run check:ads` 통과. 전역 AdSense·GA 스크립트와 `ad-slot.tsx`는 손대지 않았다. 비네트(D10)는 콘솔 설정이라 코드로 할 일이 없다.
- 공유 링크 화면에는 슬롯을 두지 않았다(1절).
