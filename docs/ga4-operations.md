# GA4 운영 리포트 사용법

`npm run ga:ops`는 최근 28일과 직전 28일을 비교해 유입·인기 글·페이지 참여·랜딩 이탈·검색 유입·구매처 클릭을 한 화면에 보여준다. 짧은 변화는 `npm run ga:ops -- 7`. **오늘은 부분일이고 데이터 처리 중일 수 있어 GA4 기간에서 제외**한다.

이번 주 실행 우선순위는 같은 페이지의 GSC 검색 노출/CTR, GA 조회당 참여시간, GA4 자동 외부 click 기반 제휴 이동을 한데 참고해 최대 5개를 제시한다. 콘텐츠 유형 소비와 랜딩 이탈률에는 직전 동일 기간 대비 변화도 추가한다. 우선순위는 점검할 후보이지 자동 판정이나 인과 분석이 아니다. 한 번에 한 항목을 바꾸고 다음 동일 기간에 결과를 비교한다.

구매처 클릭은 GA4 자동 외부 링크 이벤트 `click`의 출발 페이지(`pagePath`)와 목적지(`linkUrl`)를 현재 신발 DB 및 블로그 구매 CTA와 맞춘다. 신발의 옛 네이버·쿠팡 단축 링크도 포함한다. 2026-09-28 배포된 `purchase_link_click`은 같은 행동을 다시 측정하므로 **두 이벤트를 합산하지 않는다**. `100조회당 클릭`은 클릭 이벤트 수 ÷ 페이지 조회수 × 100이며, 구매 전환율이나 클릭한 사람의 비율이 아니다. 한 사람이 여러 번 누를 수 있다. GA4에는 제휴 주문·수수료 수익이 없으므로 실제 매출은 네이버/쿠팡 제휴 대시보드와 대조한다.

매주 같은 요일에 아래 순서로 읽는다.

1. 세션·조회·구매처 클릭의 직전 기간 대비 변화를 함께 본다. 조회만 늘고 클릭이 정체되면 상품 연결이나 방문 의도를 점검한다.
2. 급상승 글의 신발 내부 링크를 확인하고, 구매처 클릭 상위 신발의 가격·재고·링크 유효성을 확인한다.
3. `조회 ≥50, 100조회당 클릭 <5`는 **검토 후보**이지 성과가 나쁜 신발 판정이 아니다. 정보 탐색형 방문자가 많을 수 있으므로 글 맥락과 구매 버튼을 함께 본다.
4. `유입 출처 (not set)` 비율이 갑자기 늘면 날짜별 추이와 GA4 태그·동의 설정을 조사한다. 원인을 확인하기 전에는 특정 채널의 유입으로 배분하지 않는다.

콘텐츠 분석은 세 구간을 구분한다.

- `콘텐츠 유형별 소비`: `/blog`, `/shoes`, `/marathon`, `/compare`, `/recommend` 등 URL 묶음의 조회수와 참여 시간을 비교한다. 조회당 참여 시간은 `userEngagementDuration ÷ screenPageViews`이며, 실제로 화면이 활성화돼 있던 평균 시간이다.
- `오래 읽힌 페이지`: 조회 30회 이상인 경로 중 조회당 참여 시간이 긴 페이지다. 긴 글이 더 낫다는 뜻은 아니며, 계절·유입 검색어와 함께 해석한다.
- `블로그 구매처 이동`: 현재 블로그 CTA 링크와 일치한 자동 외부 클릭을 페이지 조회 및 조회당 참여시간과 나란히 본다. 매출/주문/고유 클릭 사용자로 해석하지 않는다.
- `이탈률 높은 랜딩 페이지`: 세션 20회 이상인 진입 페이지 중 참여 없는 세션 비율이 높은 경로다. GA4 이탈률은 `1 - engagementRate`에 해당한다. `(not set)`·빈 경로는 페이지 순위에서 빼고 별도로 센다. 짧은 답변 페이지는 높은 이탈률이 정상일 수도 있다.

GSC 검색 페이지는 최근 3일 지연된 기간으로 조회한다. 페이지 차원에서 노출·검색 클릭·CTR·평균 순위를 보고, 노출 50회 이상·평균 12위 이내·CTR 3% 미만을 제목/설명 점검 후보로 표시한다. GA4와 GSC는 종료일과 지표 정의가 다르므로 검색 클릭을 GA 조회수로 나눈 비율은 성과 지표로 쓰지 않는다. `npm run gsc`와 `npm run gsc:pages`는 상세 검색어·특정 글 진단용으로 계속 사용할 수 있다.

홈의 추천 시작·문제별 탐색·비교 이동·블로그/신발 이동·필터·최근 기록 등의 이벤트도 횟수로 보여준다. 이는 클릭 이벤트 수이지 고유 사용자 수나 완료율이 아니다. 현재 추천 설문 완료와 비교 구성 완료는 이벤트로 수집하지 않아 해당 흐름의 단계별 전환율은 아직 계산하지 않는다.

2026-09-29에 GA4 속성 `523714985`에 아래 이벤트 범위 맞춤 측정기준 7개를 등록했고, 관리자 목록에서 매개변수 이름까지 확인했다.

| 맞춤 측정기준 | 이벤트 매개변수 | 용도 |
| --- | --- | --- |
| 상품 유형 | `product_type` | 신발/의류 분리 |
| 상품명 | `product_name` | 클릭된 상품 비교 |
| 브랜드 | `brand` | 브랜드별 클릭 비교 |
| 판매처 | `store` | 판매처별 클릭 비교 |
| 제휴 유형 | `affiliate_type` | 네이버·쿠팡 등 링크 유형 비교 |
| 버튼 위치 | `button_position` | 상세 상단·블로그 CTA 위치 비교 |
| 의류 카테고리 | `apparel_category` | 의류 종류별 클릭 비교 |

새 `purchase_link_click` 이벤트가 이 값을 보낸다. 등록 직후 Data API 메타데이터에는 아직 나타나지 않았으므로 24~48시간 뒤 일반 보고서·탐색과 `npm run ga:ops`의 측정 상태를 다시 확인한다. 기본 `click`의 `linkUrl`·`linkDomain`은 맞춤 등록 없이 과거 데이터 분석에 계속 쓸 수 있다.

기존 명령도 그대로 유지한다: `npm run ga`는 트래픽 전체, `npm run gsc`는 검색어/검색 성과, `npm run adsense`는 수익·세션을 보여준다. `ga:ops`는 이들을 대체하지 않고 매주 콘텐츠와 구매 링크에 관해 **무엇을 확인할지**만 추린다.
