# 러닝카드 S6 — 판정 연출(약 10초)

운영자 요청(2026-10-10 00시): 기록 입력부터 결과 표지까지 모션을 더 매끄럽고 화려하게, 특히 결과가 나오기 전 10초쯤 눈길을 끄는 연출, 그리고 광고까지 매끄럽게 이어지는 흐름.

## 바꾼 것

| 구간 | 전 | 후 |
|---|---|---|
| 01–07 각인(입력) | 동전이 소켓에 떨어지고 부조가 솟는다 | + 떨어지는 순간 작은 불꽃 12개·링 1개(`strikeCoin`) |
| 07 → 결과 표지 | 카메라 이동 0.86초 후 명판 각인, 약 1.5초 | **마운트 첫 완료만** 약 10초: 메달이 빛 아래 흔들리고, 동전 7개를 차례로 다시 치며 기록을 카운트업(1.3–5.8초) → 22인물 이름 셔플이 느려지며(5.9–8.8초) → 명판 각인에 섬광·충격 링·불꽃 96개·화면 흔들림·카메라 반동(8.8–9.0초) → 이름 0.56초 유지 → 오버레이 글자가 먼저 빠지고 완료 패널이 들어온다 |
| 결과 표지 → 분석 | '분석 펼쳐보기' 버튼 정적 | 판정 직후 버튼에 광택이 3번 지나가고 화살표가 3번 내려간다 |
| 결과 카드 | 정적 | 단락이 화면에 들어오며 떠오른다(CSS `animation-timeline: view()`, 지원 브라우저만). **광고 칸 `.ad-slot`은 제외** |

- 건너뛰기 버튼이 연출 내내 오른쪽 아래에 있다. 누르면 명판을 바로 치고 패널을 보인다.
- 모션 줄이기·느린 렌더러(`stillMedal`)에서는 연출이 아예 열리지 않는다(기존 즉시 전환 그대로).
- WebGL 없음(평면 메달)에서는 3D 흔들림·동전 들어올림 없이 글자·불꽃·섬광만 돈다. 명판은 8.8초에 친다.
- 다시 다듬기로 떠났다 돌아오면 연출 없이 기존 각인만(마운트당 1회).

## 광고

- `AdSlot`·`layout.tsx`·광고 로딩은 손대지 않았다. 결과 카드는 지금처럼 명판 각인 직후(`onReveal`) 마운트되고 그때 `push({})` 한다.
- **보상형(시청하면 결과를 보여 주는) 광고는 만들지 않았다.** 일반 디스플레이 광고에 보상을 거는 건 AdSense 정책 위반 소지가 있고(추정: 무효 트래픽·유도 노출 조항), 웹 보상형은 AdSense 콘솔의 Offerwall 같은 Google 제공 형식으로만 가능한 것으로 안다(추정, 이번에 1차 문서 미확인). 판정 전환 비네트는 D10(2026-10-02)에서 이미 쓰지 않기로 했다.

## 미검증

- 실기기(iOS Safari·안드로이드 Chrome)의 프레임 속도·발열. 연출 10초 동안 WebGL이 매 프레임 그림자까지 다시 그린다.
- 실제 광고가 채워졌을 때의 결과 카드·자동 광고(앵커)와 버튼 겹침.
- 10초 연출이 이탈률에 주는 영향 — GA `runner_result_viewed` 대비 `runner_input_step_completed` 7단계 비율을 배포 전후로 비교할 것.
- 키보드·스크린리더: 건너뛰기는 버튼이고 상태 문구를 `#medal-status`에 넣었지만 실제 낭독은 듣지 않았다.
