# 쎄러데이 디자인 시스템 — MISSION 00

> 상태: 구현 전 기준안 · 2026-08-15  
> 적용 범위: `/saturday`와 쎄러데이 Remotion 영상  
> 상위 문서: `DESIGN.md`  
> 기획 정본: `docs/superpowers/specs/2026-08-11-saturday-crew-design.md`

## 1. 디자인 한 문장

**영화처럼 입장하고, 스포츠 포스터처럼 멈추고, 나중에는 친구들의 앨범으로 남는다.**

쎄러데이는 마블을 닮은 사이트가 아니다. 어벤져스에서 빌리는 것은 `미션 → 소집 → 팀 → 결전`의 구조뿐이다. 화면의 미감은 러닝 다큐멘터리 오프닝과 독립 스포츠 매거진 사이에 둔다.

첫 공개판은 사진이 없어도 완성된 공식 티저여야 한다. 사람 대신 큰 문장, 코드네임, 거리, 날짜, 출발선 그래픽이 주연이 된다. 이후 사진이 생겨도 구조를 갈아엎지 않고 같은 프레임 안의 `media slot`만 교체한다.

## 2. 전역 디자인과의 관계

루트 `DESIGN.md`는 러닝화 비교·리뷰 서비스의 정본이다. 쎄러데이는 같은 사이트 안의 **독립 에디토리얼 특집**이므로 다음처럼 격리한다.

- 전역 토큰을 수정하지 않는다.
- `/saturday` 최상위 래퍼에서만 `--sat-*` 토큰을 선언한다.
- 전역 Pretendard 셀프호스트 자산은 그대로 재사용한다.
- 일반 페이지의 큰 라운드 카드, 하늘색 포인트, SaaS형 버튼 문법은 가져오지 않는다.
- 공통 접근성 기준, 최소 터치 영역, 정적 생성 원칙은 그대로 따른다.

## 3. 미학과 감정 곡선

### 방향: Cinematic Running Zine

| 구간 | 감정 | 화면 문법 | 속도 |
|---|---|---|---|
| MISSION HERO | 농담이 사건이 되는 순간 | 어둠, 거대한 문장, 출발선, 여백 | 느리고 긴장감 있게 |
| CREW REVEAL | 일곱 명이 모이는 순간 | 종이, 인덱스, 코드네임, 빠른 컷 | 짧고 리드미컬하게 |
| RACE TARGET | 결전 날짜가 박히는 순간 | 다시 어둠, 거대한 `11 / 15`, 정지 포스터 | 빠르게 감속 후 정지 |

### 기억에 남아야 하는 장면

첫 화면의 브랜드 로고보다 `농담은 접수됐다.`가 먼저 기억나야 한다. 마지막 화면에서는 어떤 장식보다 `11 / 15`가 커야 한다. 멤버 섹션은 인물 서열이 아니라 **7개의 동등한 출발 슬롯**으로 읽혀야 한다.

### 하지 않는 것

- 마블 로고, 방패, 히어로 컬러를 직접 모사하지 않는다.
- 보라색 그라디언트, 유리 카드, 둥근 3열 기능 카드 같은 범용 랜딩페이지 문법을 쓰지 않는다.
- 사진이 없다는 이유로 스톡 러너나 가짜 친구 얼굴을 넣지 않는다.
- 모든 문장을 중앙 정렬하지 않는다. 중앙 정렬은 히어로의 한 장면에만 제한한다.
- 스크롤을 막는 강제 인트로, 자동 재생 음향, 긴 로더를 만들지 않는다.

## 4. 색상 토큰

> **2026-08-18 전면 교체.** 1차는 AI 컷 8장(`docs/superpowers/design/saturday-cuts/`),
> 2차는 크루가 실제로 찍은 사진에서 다시 뽑았다(아래 2차 교체 주석 참조). 이전 팔레트는 사진이 없던 시절에 상상으로 정한 값이라 폐기했다.
> 특히 옛 `--sat-signal: #ff5a36` 은 **8컷 115,200 표본 픽셀 중 거리 30 이내가 0.00%**
> (최근접 거리 42) — 사진에 존재하지 않는 색이었다.

```css
[data-saturday] {
  --sat-asphalt: #060809;        /* 배경. 실측 최암부(#181e2a)보다 한 단계 아래 —
                                    배경이 사진보다 밝으면 사진이 죽는다 */
  --sat-asphalt-soft: #1c2430;   /* 일출컷 p15 — 노면 그늘 */
  --sat-bluehour: #133142;       /* 일출컷 하늘. 그 사진의 26.61% 가 이 색이다 */
  --sat-paper: #d4cdc4;          /* 일출컷 최근접 거리 3 — 해 뜬 뒤 따뜻한 회색 */
  --sat-paper-deep: #efe9e1;     /* 하늘 최고광 */
  --sat-ink: #0a1013;
  --sat-signal: #f3cc7c;         /* 일출컷의 해 — 면·선·글자 전부 */
  --sat-signal-dark: #7a4520;    /* signal 파생 — 밝은 면 위 글자 (4.8:1) */
  --sat-concrete: #afaea0;       /* 일출컷 p85 — 하늘과 물의 회색 */
  --sat-line-dark: rgba(212, 205, 196, 0.2);
  --sat-line-light: rgba(10, 16, 19, 0.2);
  --sat-light-muted: rgba(212, 205, 196, 0.66);
  --sat-dark-muted: rgba(10, 16, 19, 0.62);
}
```

> **2026-08-18 2차 교체 — 근거를 AI 컷에서 크루의 실제 사진으로 옮겼다.**
> 실제 사진에서 재측정하니 5개 토큰 중 4개는 그대로 실재했다(bluehour 는 일출컷의 **26.61%**).
> 다만 **`--sat-signal: #c2610f`(나트륨 가로등)는 실제 사진 40,000px 중 거리 30 이내가
> 0.00%, 최근접 45** 였다 — AI가 그린 "비 온 새벽 가로등" 장면에만 있던 색이고
> 크루는 그 시간대에 뛴 적이 없다. `#ff5a36` 을 폐기한 것과 같은 잣대로 폐기한다.
> 실제 해 색은 **`#f3cc7c`**(노랑)다.

**Signal 단일 규칙** — `#f3cc7c` 는 어두운 바닥에서 대비 11:1 이라 면·선·글자를 혼자 다 한다.
이전의 `--sat-filament` 는 없앴다 — 그 토큰은 `#c2610f` 가 어두워 글자가 못 되던 문제를
우회하려고 만든 것이었고, 색이 밝아지면서 문제 자체가 사라졌다.
밝은 종이면 위 글자만 `--sat-signal-dark`(4.8:1) 로 간다.

| 토큰 | 역할 | 규칙 |
|---|---|---|
| Asphalt | 히어로·레이스 배경 | 완전한 `#000` 대신 질감이 남는 검정 |
| Paper | 크루·문서 표면 | 흰색보다 오래된 경기 프로그램 같은 온도 |
| Ink | 종이 위 본문 | 순검정보다 부드럽지만 충분한 대비 |
| Signal | 출발선·거리·선택 CTA | 한 화면 면적의 약 8% 이하 |
| Concrete | 메타데이터·비활성 선 | 작은 글자는 단독으로 쓰지 않고 크기·굵기로 보완 |

시맨틱 성공·경고·오류색은 이 티저에 거의 필요 없다. 추후 기록 입력 UI가 생기면 루트 `DESIGN.md`의 시맨틱 색을 사용하되, 공개 앨범 표면에는 Signal을 상태색처럼 남용하지 않는다.

## 5. 타이포그래피

### 폰트 역할

| 역할 | 폰트 | 대안 | 이유 |
|---|---|---|---|
| 한국어 제목·본문 | Pretendard Variable | sans-serif | 이미 셀프호스트되어 있고 한글의 굵기 전환이 안정적 |
| 영문 제목·날짜 | Archivo Black | Pretendard 900 | 압축된 스포츠 포스터의 무게와 큰 숫자 식별성 |
| 라벨·거리·인덱스 | IBM Plex Mono | ui-monospace | 선수 명단과 계측 데이터 같은 편집 리듬 |

Archivo Black과 IBM Plex Mono는 구현 시 `next/font/google` 또는 로컬 WOFF2로 `/saturday`에서만 변수 주입한다. 네트워크 의존을 없애려면 출시 전 로컬 자산으로 고정한다.

### 스케일

| 토큰 | 데스크톱 | 모바일 | 용도 |
|---|---:|---:|---|
| `display-date` | `clamp(9rem, 22vw, 24rem)` | `clamp(5.5rem, 34vw, 10rem)` | `11 / 15` |
| `display-hero` | `clamp(4rem, 9vw, 9rem)` | `clamp(3rem, 15vw, 5.5rem)` | 핵심 훅 |
| `display-section` | `clamp(3rem, 6vw, 6rem)` | `clamp(2.25rem, 11vw, 4rem)` | 문단 제목 |
| `headline` | 32–48px | 24–32px | 보조 헤드라인 |
| `body` | 18–22px | 16–18px | 서사 문장 |
| `label` | 11–13px | 10–12px | 미션·인덱스·거리 |

규칙:

- 한글 제목 자간은 `-0.045em`에서 `-0.025em`, 영문 블랙 제목은 `-0.03em`을 기본으로 한다.
- Mono 라벨은 대문자와 `0.12–0.22em` 자간을 사용한다.
- 숫자는 `font-variant-numeric: tabular-nums`를 켠다.
- 모바일에서 한글은 낱말 단위로 줄을 바꾸고, `11 / 15`는 절대 두 줄로 쪼개지 않는다.
- 강조를 위해 여러 굵기와 색을 섞지 않는다. 한 문장에는 최대 한 개의 Signal 강조만 둔다.

## 6. 공간·그리드·형태

### 기본 단위

- 4px 기초 단위
- 섹션 외곽 여백: 모바일 20px, 태블릿 32px, 데스크톱 48–72px
- 본문 최대 폭: 680px
- 무대 최대 폭: 제한 없음. 배경과 큰 숫자는 항상 full bleed
- 섹션 최소 높이: `100svh`, 최소 콘텐츠 높이는 별도 확보

### 그리드

| 폭 | 열 | 거터 | 용도 |
|---|---:|---:|---|
| 0–767px | 4 | 12px | 세로 스택, 한 손 스캔 |
| 768–1199px | 8 | 20px | 태블릿과 작은 노트북 |
| 1200px+ | 12 | 24px | 비대칭 에디토리얼 배치 |

### 형태

- 기본 반경은 `0`. 버튼과 배지는 최대 2px, 원형 상태점만 999px.
- 구분선은 1px, 출발선과 핵심 액센트는 2–4px.
- 그림자보다 색면·선·겹침으로 깊이를 만든다.
- 사진 프레임은 직사각형이며, 폴라로이드 흉내나 무작위 회전은 Mission Log에서만 제한적으로 허용한다.

## 7. 질감과 이미지

### 사진 없는 MISSION 00

CSS만으로 다음 재료를 사용한다.

- 1–2% 투명도의 미세 노이즈 오버레이
- 아스팔트의 수평 마찰 흔적
- 출발선·차선·크롭 마크
- 멤버 번호 `01–07`
- 거리 문자열 `42.195 KM`, `10 KM`
- 크루 전체를 나타내는 `7 × START LINE`

질감은 텍스트 판독을 방해하지 않아야 하며, 배경 노이즈 이미지를 쓸 경우 30KB 이하 WebP/AVIF 또는 작은 반복 PNG로 제한한다.

### 사진이 생긴 뒤

우선 수집할 얼굴 없는 장면:

1. 신발끈 묶기
2. 러닝 워치 시작 버튼
3. 발 착지와 그림자
4. 밤 도로의 불빛
5. 대회 접수 화면
6. 일곱 켤레 신발

모든 사진은 색을 완전히 통일하려 하지 않는다. 대신 동일한 검정 레벨, Signal 자막, 프레임 비율로 한 앨범처럼 묶는다.

## 8. 핵심 컴포넌트 테마

### Mission Header

- 좌상단 `쎄러데이 / SATURDAY RUNNING CREW`
- 우상단 `첫 번째 이야기 · 일곱 명 접수 완료` (모바일은 앞 구절만)
- 사운드는 실제 음원이 있을 때만 음소거 토글
- 투명 배경, 스크롤 뒤 최소한의 Asphalt 블러
- 로고보다 지금 어떤 이야기인지가 먼저 보인다.

> 2026-08-15 변경: `MISSION 00 / RECRUITMENT CLOSED`에서 교체했다. §14 결정 로그 참조.

### Mission Hero

- 첫 정지 프레임: `풀마라톤, 다 같이 한번 해볼까?`
- 다음 프레임: `웃자고 한 말이었다.`
- 결정 프레임: `농담은 접수됐다.`
- 보조문: `아무도 진심은 아니었다. 접수 전까지는.`
- 바닥 메타: `2026.11.15 / 손기정평화마라톤`
- 사진 없는 버전은 문장 사이를 지나가는 얇은 출발선으로 전환한다.

### Crew Reveal

- 제목: `이 말에 책임질 일곱 명.`
- 서브: `잘 뛰는 사람을 모은 게 아니다. 같이 출발할 사람을 모았다.`
- 7개 슬롯은 크기와 시선 무게가 동등하다.
- `01–07 / 코드네임 / 거리`만 공개한다.
- 로스터: 재춘, 감자, 형가, 기태, 지자, 남길 — FULL / 광묵 — 10K
- 종결 데이터: `6 × 42.195 KM / 1 × 10 KM / 7 × START LINE`
- 유머는 보조 라벨에서만 쓴다: `준비 상태는 제각각. 접수 상태는 전원 완료.`

### Race Target

- eyebrow: `그날, 파주에서` (2026-08-15 변경, 이전 `FINAL MISSION / 2026 · PAJU`)
- 주인공: `11 / 15`
- 대회명: `손기정평화마라톤`
- 훅: `11월 15일, 농담의 결말을 보러 간다.`
- 종결: `결말은 아직 없다. TO BE CONTINUED.`
- 다음 기록 예고: `다음 이야기는 첫 러닝부터`
- Instagram CTA는 링크가 확정되기 전 버튼처럼 보이지 않는 텍스트 링크로 둔다.

### Member Frame

- `member-index` 2자리, `code-name`, `distance`, 선택적 `media`
- 프로필 카드가 아니라 영화 크레딧과 선수 엔트리 사이의 형태
- hover는 보조 장치다. 모바일·키보드에서도 동일한 정보를 기본 노출한다.

## 9. 모션·스크롤·사운드

### 모션 토큰

```css
[data-saturday] {
  --sat-motion-micro: 120ms;
  --sat-motion-short: 240ms;
  --sat-motion-medium: 480ms;
  --sat-motion-cinema: 900ms;
  --sat-ease-enter: cubic-bezier(0.16, 1, 0.3, 1);
  --sat-ease-move: cubic-bezier(0.65, 0, 0.35, 1);
}
```

### 구간별 규칙

- Hero: `질문 → 빈 호흡 → 웃자고 한 말 → 농담은 접수됐다` 네 beat로 나뉜다. 한 프레임에는 한 문장만 주연으로 둔다.
- Crew: `개별 상태 → 모였다. → 7명 엔트리 → 거리 합계` 네 beat로 조립된다.
- Race: `날짜 접근 → 프레임 점유 → 정지 포스터 → TO BE CONTINUED blackout` 네 beat로 닫힌다.
- 각 문단은 native scroll 안에서 sticky stage를 사용한다. Hero 2.8 화면, Crew 3.4 화면, Race 3 화면의 시간을 배정한다.
- 기본 구현은 CSS custom property + 단일 requestAnimationFrame scroll director다. GSAP은 영상 프레임 스크럽이 생길 때만 검토한다.
- `transform`과 `opacity` 위주로 움직이고 레이아웃 속성 애니메이션은 피한다.

### 씨네마틱 판정 기준

정지 화면 한 장이 영화 포스터처럼 보이는 것만으로는 씨네마틱으로 판정하지 않는다. 다음 네 조건을 모두 만족해야 한다.

1. 앞 장면의 정보가 사라진 뒤 다음 장면이 들어오는 시간 순서가 있다.
2. Hero의 개인적 농담이 Crew의 집단 엔트리로 변하는 인과가 보인다.
3. Race 날짜가 움직이다가 완전히 멎는 속도 대비가 있다.
4. 마지막 blackout에서는 `TO BE CONTINUED`가 주인공으로 남고, 그 아래에 `다음 이야기는 첫 러닝부터`만 작은 보조문으로 둔다.

### 스크롤 제어

- 첫 버전에서 강제 스크롤 스냅은 쓰지 않는다.
- 데스크톱과 모바일 모두 native scroll을 유지한 채 stage만 잠시 sticky로 둔다. 화면을 강제로 넘기거나 스크롤 위치를 보정하지 않는다.
- 뒤로가기·앵커 이동·새로고침 후 위치 복원이 깨지면 sticky 연출을 제거한다.

### 사운드

- v1은 무음으로 완성한다.
- 음원이 생겨도 기본값은 OFF다.
- 사용자 클릭 후에만 재생하고, 토글 상태와 명확한 라벨을 제공한다.
- 음향이 없어도 모든 서사와 타이밍을 이해할 수 있어야 한다.

### 모션 감소

`prefers-reduced-motion: reduce`에서는 모든 문장과 멤버가 최종 상태로 보이고, sticky·parallax·scrub을 제거한다. 콘텐츠 순서와 의미는 그대로 유지한다.

## 10. 반응형 핵심 규칙

### 모바일

- 실제 기준 폭: 360, 390, 430px
- `padding-top: max(20px, env(safe-area-inset-top))`
- 하단 CTA는 `env(safe-area-inset-bottom)`을 포함한다.
- Hero 핵심 문장은 상·하단 브라우저 UI와 겹치지 않도록 중앙 60% 안전 영역에 둔다.
- Crew 슬롯은 1열 명단이 기본이며, 코드네임을 잘게 쪼개는 2열 카드 그리드를 피한다.
- `11 / 15`는 폭을 넘어 잘리는 연출 대신 화면 안에서 최대 크기로 맞춘다.

### 데스크톱

- 텍스트와 그래픽을 12열에서 의도적으로 어긋나게 배치한다.
- 멤버는 7열 균등 카드가 아니라 `4 + 3` 또는 긴 엔트리 스트립으로 구성한다.
- 초광폭에서도 핵심 텍스트의 읽기 폭은 제한하고, 빈 공간을 장면의 일부로 사용한다.

## 11. 접근성·성능 기준

- 모든 텍스트 대비는 WCAG AA 이상. Signal 위 작은 흰 글자는 금지하고 Asphalt 또는 Ink를 쓴다.
- 키보드 포커스는 Signal 2px + Asphalt/Paper offset으로 표면별 재정의한다.
- 의미 있는 콘텐츠는 HTML에 먼저 존재하고 모션은 그 위에 얹는다.
- 장식 번호·차선·노이즈는 `aria-hidden="true"`.
- 버튼과 링크의 최소 터치 영역 44×44px.
- `svh`를 우선하고 `vh` 폴백을 둔다.
- 첫 화면 JS는 D-day와 모션 컨트롤에 필요한 최소량만 허용한다.
- 사진이 생기면 `sizes`, 고정 비율, 우선순위를 명시해 CLS를 막는다.
