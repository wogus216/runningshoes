## 1. raw 값 잔재 — 계획서 Step 1

계획서의 grep 대상은 `blue-*` · `rgba(14,165,233)` · `#0ea5e9/#0284c7/#38bdf8` 였다.
**이 중 hex 3종이 실제로 남아 있었다.**

| 검사 | 초기 | 조치 후 |
|---|---|---|
| `blue-[0-9]` 유틸리티 | 0 | 0 |
| `rgba(14,165,233)` | 0 | 0 |
| `#0ea5e9` / `#0284c7` / `#38bdf8` | **6건 / 3파일** | 0 |
| teal- / emerald- / blue- 유틸리티 | 0 (`8531b5c` 에서 정리됨) | 0 |
| 구 크림·네이비 리터럴(#FDFCFA 등 5종) | 0 (`4234da6` 에서 정리됨) | 0 |
| 차가운 rgba 틴트 | **17건 / 17파일** | 0 |

### 1-1. 구 스카이블루 그라디언트 (커밋 `2a3ea0e`)

`category-section.tsx` · `recommend/result-card.tsx` · `compare/enhanced-compare-table.tsx` 의
상단 액센트 바가 구 팔레트 hex 를 그대로 물고 있었다.

```
linear-gradient(90deg,#38bdf8 0%,#0ea5e9 60%,#f97316 100%)   ← 파랑 → 파랑 → 주황
→ linear-gradient(90deg,var(--accent) 0%,var(--signal-dark) 100%)
```

**웜 사이트 위에 파란 바가 렌더되고 있었다.** 신발 카테고리 섹션·추천 결과 카드·비교표는
1단계 배포 범위(§13)라 그대로 나갈 뻔했다.

### 1-2. 차가운 rgba 틴트 (같은 커밋)

`rgba(241,248,255)` `rgba(239,248,255)` `rgba(231,244,255)` `rgba(236,248,255)`
`rgba(242,248,255)` `rgba(239,246,255)` `rgba(239,247,255)` `rgba(248,250,252)` —
전부 **파란기 도는 흰색** 그라디언트다. 17파일에서 웜(`247,244,237` / `239,234,224`)으로 교체.

> 왜 이전 라운드가 놓쳤나: `8531b5c` 는 **유틸리티 클래스명**(teal-/emerald-/blue-)을 grep 했다.
> 이 둘은 임의값(`bg-[...]`) 안의 리터럴이라 클래스명 검색에 걸리지 않는다.
> **팔레트 검사는 클래스명과 리터럴을 따로 훑어야 한다.**

## 3. 렌더 검수 — 계획서 Step 2

`npm run build` 후 `npx serve out` 으로 실제 렌더를 훑었다. 육안 대신 **DOM 전수 스캔**을 썼다 —
모든 요소의 `backgroundColor`/`color`/`borderColor`/`fill`/`backgroundImage` 를 읽어
채도 있는(스프레드 ≥ 45) 색 중 웜 토큰이 아닌 것을 뽑는 방식이다.

| 페이지 | 팔레트 밖 유채색 |
|---|---|
| `/` (새 홈) | 0 |
| `/compare` | 0 |
| `/shoes/[slug]` | 1 → 조사 결과 정당(아래) |
| `/best/beginner` | 0 |
| `/marathon` | 0 |
| `/faq` | 0 |

### 3-1. 네이버 브랜드 색 — 정당하나 **버그를 동반**했다 (커밋 `d3a8f7c`)

`#03c75a` 는 네이버 브랜드 색이고 구매 링크에 쓰는 게 맞다. 다만 배경값이

```
bg-[#03c7510]   ← 7자리. #RRGGBB + 알파(10) 규칙에서 한 글자가 빠졌다
```

라 **Tailwind 가 클래스를 아예 생성하지 않았고, 네이버 버튼만 배경 없이 렌더되고 있었다.**
`bg-[#03c75a10]` 으로 정정(빌드 CSS 에 `.bg-\[\#03c75a10\]` 생성 확인).
쿠팡·ABC마트·무신사는 8자리라 정상이었다.

## 4. 범위 밖으로 남기는 것

### 마라톤 상세의 거리 배지 (cyan / violet)

`marathon/[id]/page.tsx` 가 `하프 = bg-cyan-100` · `울트라 = bg-violet-100` 을 쓴다.
빌드 결과 **마라톤 상세 ~100페이지에 각 2건씩** 렌더된다. `shoe-bridge.tsx` 의
`안정화 = violet` 도 같은 계열이다.

**고치지 않았다.** 근거:
- 스펙 §1 이 마라톤 페이지를 명시적으로 제외하고, §13 확산 로드맵도 마라톤을 5단계로 둔다
- 거리·카테고리를 색으로 구분하는 **범주형 색 체계**라, 웜 팔레트로 바꾸면 구분이 사라진다.
  QA 가 단독으로 결정할 사안이 아니라 디자인 판단이 필요하다

→ 5단계에서 "범주 구분을 색이 아닌 무엇으로 할지"와 함께 결정할 것.

### 소스에는 있으나 렌더되지 않는 것

`faq/page.tsx` 의 `bg-green-500`/`bg-cyan-500`, `about/page.tsx` 의 `bg-green-100`,
`types/brand.ts` 의 cyan — **빌드 HTML 에서 0건**이다(도달하지 않는 코드 경로).
Tailwind 는 클래스를 생성하지만 마크업에 나오지 않아 화면에는 영향이 없다.
죽은 코드 정리 대상이지 팔레트 문제가 아니다.

**통과.** 실제로 렌더되는 팔레트 밖 색은 0이고, 대비 기준 미달도 0이다.

임의값 안의 리터럴(클래스명 grep 회피) · hover 상태 대비(정적 스캔 회피) ·
깨진 hex(빌드는 통과하고 클래스만 조용히 사라짐).
