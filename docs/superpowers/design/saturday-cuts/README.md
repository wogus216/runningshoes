# 쎄러데이 시네마틱 4컷 — 재생성 지시서

`/saturday` 와 Remotion 티저 2종이 함께 쓰는 사진 자산을 다시 뽑는다.
생성기는 **ChatGPT 이미지 생성(gpt-image-1)** 을 전제로 문법을 맞췄다.

## 왜 다시 뽑는가 (2026-08-15 실측)

측정 사양 — 분석 단위: 이미지 1장 · 모집단: `public/images/challenge/saturday/` 의
시네마틱 컷 4장(poster 제외) · 집계: 그레이스케일 변환 후 전체 픽셀 평균·표준편차
(`sharp().greyscale().stats()`) · 시점: 2026-08-15 워킹트리

| 컷 | 크기 | 평균밝기 | 표준편차 |
|---|---|---|---|
| `laces` | 1080×1920 | 24.1 / 255 (9.5%) | 32.0 |
| `foot-strike` | 1080×1920 | 30.8 (12%) | 36.3 |
| `watch-start` | 1080×1920 | 34.3 (13%) | 25.2 |
| `seven-runners` | 1080×1920 | 42.8 (17%) | 37.7 |

세 가지 문제가 나온다.

1. **가로컷이 0장이다.** 4장 전부 9:16 세로. 데스크톱 1440×900 풀블리드에 `cover`로
   채우면 가로 1.33배 확대 + 세로 35%만 남기고 잘린다. DPR 2 화면에서는 2.67배 확대라
   물리적으로 흐리다.
2. **밝기 계단이 없다.** 4장이 9.5~17% 구간에 몰려 있다(일반 사진은 40~50%대).
   특히 `seven-runners` 는 종이색(`#f2efe7`) 배경의 크루 섹션에 놓이는데 야간 사진이라
   `opacity .18` 까지 깎아야 했고, 그것이 화면이 회색 죽처럼 보이는 직접 원인이다.
   → **크루 컷은 밝게 다시 찍는다.** 그러면 오버레이로 사진을 죽이는 코드 자체가 사라진다.
3. **`watch-start` 가 약하다.** 표준편차 25.2로 가장 평평하고(대비 없음), 손가락 해부학이
   어색하다. → **손을 프레임에서 뺀 구도로 재설계한다.**

## 밝기 계단 (이번 재생성의 핵심 설계)

스크롤이 내려갈수록 화면이 밝아진다. 어두운 새벽에 혼자 준비해서, 밝아진 하늘 아래
일곱 명으로 끝난다.

| # | 컷 | 역할 | 현재 | **목표** | 페이지 배경 |
|---|---|---|---|---|---|
| 01 | `laces` | 아직 캄캄한 새벽, 혼자 준비 | 9.5% | **22%** | Asphalt |
| 02 | `watch-start` | 출발 신호 (손 제거) | 13% | **30%** | Asphalt |
| 03 | `foot-strike` | 첫 착지, 물 튀김 | 12% | **38%** | Asphalt |
| 04 | `seven-runners` | 일곱 명 집결 | 17% | **62%** | **Paper** |

목표 밝기는 프롬프트의 노출 지시로 유도하고, 최종 미세 조정은 후처리에서 맞춘다.
생성 단계에서 ±10%p 안에 들어오면 충분하다.

## 출력 규격

ChatGPT 이미지 생성은 크기가 고정이다. 16:9 / 9:16 은 지원하지 않는다.

| 용도 | 지정할 크기 | 실제 비율 |
|---|---|---|
| 가로 (`-wide`) | **1536 × 1024** | 3:2 |
| 세로 (`-tall`) | **1024 × 1536** | 2:3 |

세로컷은 현재 파일(1080×1920)보다 폭이 56px 작다. **세로는 해상도로 이득이 없고
구도와 밝기로만 이긴다.** 가로는 현재 0장이므로 전부 순증이다.

## 작업 순서

1. **ChatGPT 대화 하나**를 열고 8장을 **01 → 04 순서로 이어서** 뽑는다.
   같은 대화에서 이어 생성하면 톤 일관성이 눈에 띄게 좋아진다.
   두 번째 장부터는 프롬프트 앞에 `Same photographic style, same location and lighting
   as the previous image.` 를 붙인다.
2. 각 장을 받을 때마다 아래 **공통 합격 기준**과 파일별 합격 기준을 눈으로 확인한다.
   하나라도 걸리면 다시 뽑는다. 애매하면 통과시키지 말 것 — 후처리로 못 고친다.
3. 받은 원본(PNG)을 아래 경로에 그대로 넣는다. 이 폴더는 git에 올라가지 않는다.

   ```
   private/challenge/cuts-raw/
     01-laces-wide.png
     02-laces-tall.png
     03-watch-start-wide.png
     04-watch-start-tall.png
     05-foot-strike-wide.png
     06-foot-strike-tall.png
     07-seven-runners-wide.png
     08-seven-runners-tall.png
   ```

4. 넣었다고 알려주면 이후는 내가 한다 — 밝기 실측·톤 통일·2배 업스케일·WebP 변환·
   두 배포 경로(`public/images/challenge/saturday/`, `video/saturday-teaser/public/images/`)
   반영·페이지 레이아웃 수정·Remotion 2종 재렌더·검증.

8장을 다 못 채워도 된다. **받은 것부터 순서대로 반영한다.**
