### ⚠️ 430 / 360 은 기준(8,000px)을 4~7% 넘는다

섹션 합만 보면 7,081 / 7,280 으로 **모바일 시안 실측(6,945~7,092)과 거의 같다.**
초과분은 전부 **섹션 밖**이다(430 기준 1,251px):

| 요소 | 높이 | 비고 |
|---|---|---|
| 사이트 푸터 | 556px | 기존 자산, 이번 범위 밖 |
| 광고 블록 | 529px | 280px 예약은 CLS 방지용(§7). 줄이면 CLS 가 나빠진다 |
| 헤더 | 70px | 기존 자산 |
| `main` 상하 패딩 | 64px | 레이아웃 컨테이너(아래 4번) |

시안은 자체 푸터를 쓰는 독립 HTML 이라 **실사이트 푸터(556px)가 빠져 있었다.**
같은 잣대로 비교하려면 섹션 합을 봐야 하고, 그 값은 기준을 만족한다.

→ 더 줄이려면 푸터·광고 예약·레이아웃 패딩을 건드려야 하는데 셋 다 이번 범위 밖이다.
   **디자인을 깎아 숫자를 맞추지 않고 그대로 보고한다.**

### 이 QA 에서 고친 것 (커밋 `f0a1e2b`)

초기 측정은 430 에서 **8,742px**, 768 에서 **8,234px** 였다. 원인 둘 다 시안과의 불일치였다.

1. **인덱스 기본 노출이 모바일에서도 16이었다.** 스펙 §5.2 는 "데스크톱 16 / 모바일 12".
   → 12 로 맞춰 인덱스가 2,121 → 1,697px (-424px)
2. **모바일 섹션 패딩이 52px 이었다.** 모바일 시안 실측은 34px(이어보기는 26px).
   → 섹션 6개에서 약 216px 회수

두 수정으로 768 은 **7,996px 로 기준 내에 들어왔다.**

### 그 밖 도달 기준

| 항목 | 기준 | 실측(1440) | |

| 광고 도달 깊이 | 55~70% | 62% | ✅ |

## 4. GA4 중복 발화 — 계획서 Step 5

`window.gtag` 를 스텁으로 갈아끼우고 실제 클릭·스크롤로 확인했다.

| 이벤트 | 동작 | 발화 | |
|---|---|---|---|
| `home_shoe_index_expand` | 확장 2회 | 2 | ✅ 동작 횟수와 일치 |
| `home_filter_apply` | 트레일 선택 → 전체 복귀 | 1 | ✅ 필터 해제는 미발화 |
| `home_trust_methodology_open` | 펼침 → 접기 → 펼침 | 2 | ✅ 펼칠 때만 |
| `home_ad_view` | 광고 도달 → 위로 → 재도달 | 1 | ✅ 세션당 1회 |

> 첫 측정에서 `home_trust_methodology_open` 이 4회로 나왔는데, **테스트가 틀렸다** —
> `details.open = true` 가 native `toggle` 을 쏘는데 그 위에 합성 이벤트를 또 dispatch 했다.
> 실제 클릭으로 다시 재면 1회다. 계측 코드를 먼저 의심할 것.

### 이 QA 에서 배선한 것 (커밋 `f0a1e2b`)

`home_ad_view` 가 **스펙 §8 목록에만 있고 아무 데서도 발화하지 않았다.**
`HomeAdSlot` 을 만들어 IntersectionObserver(threshold 0.5)로 도달을 한 번만 기록한다.
공용 `AdSlot` 에 넣지 않은 이유: 다른 페이지에서도 `home_ad_view` 가 발화하게 된다.
**슬롯 ID(`8774844686`)·개수(1)·위치(인덱스↔에디토리얼)는 그대로다.**

홈 성과는 순회로 판단하지만(§1), 개편이 광고 도달률을 떨어뜨리지 않았는지는
배포 후 확인해야 하고 그러려면 이벤트가 필요하다.

## 5. 이 QA 에서 잡은 버그

**모바일 → 데스크톱 복귀 시 인덱스가 12행에 갇혔다.** 브레이크포인트 핸들러가
`shown === initialCount`(16)로 비교해, 모바일에서 12가 된 뒤에는 조건이 영영 거짓이었다.
현재 기준값을 ref 로 들고 비교하도록 고쳤다. 데스크톱 16행 복귀 · 확장 40행 정상 확인.

리사이즈를 실제로 해보지 않았으면 못 잡았을 종류다.
