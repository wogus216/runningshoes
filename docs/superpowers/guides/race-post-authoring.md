# 대회 글 쓰는 법 (2026-08-19 표준)

`BlogPost.raceMeta`(`src/types/blog.ts`)를 넣으면 이 구성 표준이 적용되고
`npm run validate`(8번 섹션)가 자동으로 검사한다.

**넣지 않으면 기존 방식 그대로다.** 기존 대회 글 70편은 이 필드가 없어 검사 대상이
아니고 렌더도 바뀌지 않는다. 새 표준은 `raceMeta`를 넣는 순간부터 그 글에만 적용된다.

## `raceMeta` 필드 전체

| 필드 | 필수 | 설명 |
|---|---|---|
| `displayTitle` | 필수 | 화면용 제목. 검색용 `title`과 별개, 40자 이하 |
| `displaySubtitle` | 선택 | 부제 |
| `raceDate` | 필수 | 대회일. `'YYYY-MM-DD'` |
| `registrationStart` | 선택 | 접수 시작. `'YYYY-MM-DDTHH:mm'` |
| `registrationEnd` | 선택 | 접수 마감 |
| `registrationVia` | 선택 | 접수처 (예: `'YES24 티켓'`) |
| `action` | 선택 | `{ what, how }` — 지금 뭘 준비해야 하는지 |
| `facts` | 필수 | 핵심 카드 4~6개, `RaceFact[]` |
| `highlights` | 필수 | 이 대회만의 것 2~4개, `RaceHighlight[]` |
| `elevation` | 선택 | 고도 프로파일, `RaceElevationPoint[]` |
| `elevationSource` | 선택 | 고도 수치 출처. `elevation`이 있으면 사실상 필수(경고) |
| `marathonId` | 선택 | 마라톤 DB(`src/lib/data/marathon/`) 연결 id |

날짜는 전부 **KST 기준 문자열**이다. `RaceFact`는 `{ label, value, sub? }`,
`RaceHighlight`는 `{ badge, title, desc }` (`badge`는 `'3×'`·`'12월'`·`'국내 유일'`
같은 표식 — 순번 `01/02/03`은 쓰지 않는다).

    displaySubtitle: '광안대교·부산항대교·남항대교를 하루에 다 건넌다',

## 지켜야 할 것 — 검사 규칙 10종

전부 `src/lib/blog/race-meta-rules.ts`의 `checkRaceMeta()`가 검사하고,
`npm run validate` 실행 시 자동으로 돈다(별도 명령 없음).

| 규칙 | 수준 | 왜 |
|---|---|---|
| `facts-count` — `facts` 4~6개 | 에러 | 적으면 그리드가 비고 많으면 스캔이 안 된다 |
| `highlights-count` — `highlights` 2~4개 | 에러 | 1개면 "이 대회만의 것"이 성립 안 한다 |
| `no-tldr` — 본문에 `class="tldr"` 금지 | 에러 | 3줄 요약은 접수 정보 반복이었다 |
| `slug-no-year` — slug에 `20\d\d` 금지 | 에러 | 매년 같은 URL이 권위를 쌓는다 |
| `display-title-length` — `displayTitle` 40자 이하 | 에러 | 넘으면 414px 화면에서 3줄이 된다 |
| `display-title-same` — `displayTitle`이 `title`과 동일 | 경고 | 검색 제목을 그대로 복사했다면 별도 필드를 둔 의미가 없다 |
| `race-date-parse` — `raceDate`가 날짜로 파싱 가능 | 에러 | 파싱 실패하면 상태 배지 계산이 통째로 죽는다 |
| `registration-order` — 접수 마감 ≥ 접수 시작 | 에러 | 역전되면 상태가 영구 closed로 고정된다 |
| `shoe-links` — 고유 신발 링크 3개 이상 | 경고 | 3개 이상이면 자동 신발 카드 브릿지가 렌더되지 않는다(수동 링크와 중복 방지) |
| `elevation-source` — `elevation`이 있는데 `elevationSource` 없음 | 경고 | 출처 없는 고도 그래프는 실측처럼 읽힌다 |

## 본문에 쓰는 것 / 안 쓰는 것

**쓴다** — 표가 답할 수 없는 것. "4:30과 5시간이 헷갈리는 이유", 코스 전략, 다른
대회와의 선택 기준, 이 대회만의 리스크(오르막·방풍·기록 조건 등).

**안 쓴다** — 접수일·정원·참가비 재서술. 그건 `facts`와 맨 아래 요강표가 이미 한다.
본문에서 같은 숫자를 다시 서술하면 갱신할 때 두 곳이 따로 놀다가 어긋난다.

전체 요강표는 **본문 맨 아래**에 둔다. 대회마다 항목(교통편·기념품·부문별 상금 등)이
달라 `raceMeta`로 강제하지 않고 자유 서식 표로 남긴다.

## 고도 프로파일

수치가 **공개된 대회만** 넣는다.

```typescript
    elevation: [{ km: 0, m: 5 }, { km: 12, m: 32 }, /* ... */],
    elevationSource: '대회 공식 코스 안내 (2026-08-19 확인)',
```

**공개되지 않았으면 넣지 않는다.** 대충 그린 산 모양은 실측처럼 읽힌다.
대회 공식 코스맵 **이미지**는 저작권상 쓰지 않는다 — 근거는 스펙
`docs/superpowers/specs/2026-08-19-race-post-structure-design.md` 9-1절.
수치만 확보되면 사이트가 자체 SVG로 그린다.

## 검색 표면 — `title`과 `description` (2026-08-31 추가)

본문이 아무리 좋아도 **검색 결과에서 안 눌리면 읽히지 않는다.** 마라톤 DB 페이지는
코드가 자동으로 만들지만(`marathon/[id]/page.tsx`), 블로그 대회 글은 사람이 쓰므로
같은 원칙을 손으로 지켜야 한다.

**① 검색어 어순을 그대로 앞에 놓는다** (2026-09-01 네이버 실측으로 추가)

```
✗  디즈니런 2026 인천 …          ← 우리가 이랬다
◎  2026 디즈니런 인천 …          ← 상위 10건 중 8건이 이 어순
```

검색어가 `2026 디즈니런 인천`인데 우리는 `디즈니런 2026 인천`이었다. 네이버는 제목의
정확 일치를 크게 보므로 어순만 어긋나도 잃는다. **대회명을 쓸 때 "사람이 실제로
검색창에 치는 순서"를 먼저 정하고, 그 순서로 `name` 을 적는다.**

**② 의도 키워드를 대회명 **바로 뒤**에 붙인다**

```
✗  2026 손기정평화마라톤 (제22회) | 임진각 (경기 파주)
◎  2026 손기정평화마라톤 접수·참가비·코스 | 11월 15일 임진각
```

`(제22회)`·사이트명처럼 아무도 안 찾는 말이 자리를 먹고 있으면 그만큼 잃는다.

### 무엇을 붙일 것인가 — 네이버 상위 10건 실측 (2026-09-01)

"2026 디즈니런 인천" 1페이지 제목을 전수로 셌다:

| 요소 | 10건 중 |
|---|---|
| 검색어 어순 그대로 시작 | **8** |
| 신청 / 신청방법 | 7 |
| 코스 | 6 |
| **총정리** | 5 |
| 접수 | 5 |
| 참가비·비용 | 4 |
| **기념품** | 3 |
| 괄호 후킹 `(티켓팅 성공 꿀팁)` `(선착순 꿀팁)` | 3 |
| 날짜 | 거의 없음 — 대신 "오늘 접수 오픈" |

실제 예: `2026 디즈니런 인천 신청 방법 및 코스 총정리 (티켓팅 성공 꿀팁)`

> ⚠️ **이 표가 Bing 표본을 대체한다.** 2026-08-31 에 Bing 31건으로 "기념품 3%"라 적었는데
> 네이버 실측에서는 **30%** 였다. 열 배 차이다. Bing 은 한국 점유율이 미미해 대리 지표로
> 쓸 수 없다. 구글은 자동화를 캡차로 막아(Chrome MCP·Playwright 모두 실패) 직접 못 센다 —
> **경쟁사 제목을 볼 때는 네이버를 쓰거나 사람에게 스크린샷을 받는다.**

**③ `og:title` 을 `<title>` 과 맞춘다** (2026-09-01 추가)

**네이버는 대회 페이지에서 `og:title` 을 검색 결과 제목으로 쓴다.** 실측으로 확인했다 —
`<title>` 에 의도 키워드를 붙여도 `og:title` 이 옛 형식이면 네이버에는 하나도 안 나간다.
경로별로 다르다는 것도 확인됐다(신발은 `title` 을 쓴다). 확인 방법:

```bash
npm run naver:rank -- "site:allrunabout.com/marathon"
```

출력의 제목을 `out/` 산출물의 `title`·`og:title` 과 대조한다. 어느 쪽과 일치하는지가 답이다.

**④ 접수가 끝난 대회에 "접수"를 걸지 않는다**

마감된 대회에 접수를 약속하면 클릭 후 실망을 주고 장기적으로 신뢰를 깎는다.
끝난 대회는 `코스·참가비·기념품`처럼 **여전히 유효한 정보**를 건다.

**⑤ `description`은 155자에 맞춘다**

구글이 보여주는 건 그 정도다. 그 뒤는 쓰는 만큼 버려진다. 대회명은 넣지 않는다 —
`title`이 이미 말한다. 날짜에서 연도를 빼면 20자쯤 아낀다.

**⑥ 영문 병기 괄호는 벗기되, 한글 별칭은 남긴다**

`(ASICS SEOUL SHINMUN GO FREE RUN)` 하나가 33자다. 반면 `(뉴발란스 런유어웨이)`는
장식이 아니라 **최다 유입 검색어**라(`런유어웨이` 145노출) 빼면 매칭을 잃는다.
판단 기준은 "괄호 안에 한글이 있는가"다.

### CTR 을 읽을 때 빠지기 쉬운 함정 둘

**혼합 의도 쿼리를 CTR 실패로 읽지 않는다.** "손기정마라톤"(1,284노출·최대 볼륨)은
네이버가 **인물 손기정(1912~2002)**으로 해석한다. 그 노출의 상당수는 대회를 찾는
사람이 아니라서 CTR 이 구조적으로 눌린다. 같은 페이지가 연도 붙은 쿼리에서는
3~13%를 낸다("2026 손기정 마라톤" 13.5%). **이런 페이지는 CTR% 가 아니라 클릭
절대수로 판정한다.**

**고CTR 페이지를 벤치마크하기 전에 표본을 본다.** 부산브릿지 9.6%·오사카 10.1% 는
공개 노출이 각각 43/135(32%)·169/873 뿐이다. 소규모 브랜드 검색이 만든 수치라
따라 할 패턴이 아니다. `npm run gsc:pages -- <slug>` 출력 맨 아래의 익명화 경고를
반드시 읽을 것.

**브랜드 IP 대회는 구조적으로 불리하다.** 검색어가 브랜드명인 대회(뉴발란스 런유어웨이
1.0% · 리아는 배불런 0.6%)는 브랜드 공식이 SERP 상단을 독식한다. 반대로 지자체·언론
주최 대회(강남평화 5.3% · 고프리런 5.1%)는 공식이 부실해 우리가 대안이 된다.
**같은 8위권에서 CTR 이 9배 갈린다** — 순위만 보고 판단하면 안 된다.

## 상태 배지는 손으로 적지 않는다

접수중/마감임박/마감/종료 배지는 `registrationStart`·`registrationEnd`·`raceDate`에서
**자동 계산**된다(브라우저 시각 기준 D-day). 본문에 `D-12` 같은 문구를 손으로 쓰지 않는다
— 실제로 라이브에 "D-12"가 일주일 틀린 채 서 있던 사고가 이 표준을 만든 계기다.
