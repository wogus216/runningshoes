# 러너 신화 분석 판정 엔진 v1

## 목적

최근 28일 러닝 기록을 동일한 세 개 지표로 요약하고, 그 기록과 목표에 가장 가까운 그리스·로마 신화 인물 한 명을 선택한다.

- 공개 지표: `지구력`, `훈련 자극`, `회복 여유`
- 결과: 12신 가문에 속한 36명 중 대표 인물 1명
- 판정 비중: 러닝 데이터 80%, 목표 20%
- 입력 방식: 워치 연동과 직접 입력은 같은 정규화 데이터로 계산
- 출력 방식: 입력 출처, 예비/정식 여부, 신뢰도 등급은 사용자에게 표시하지 않음
- 안전 경계: `회복 여유`는 생리학적 회복 상태나 부상 위험 진단이 아니라 훈련 간격과 부하의 여유를 나타내는 행동 지표

## 현재 상태

기존 `src/lib/runner-archetype.ts`는 `/recommend` 설문 결과를 여섯 명의 삼국지 인물로 번역한다. 목적, 주간 거리, 부상 이력 같은 조건문으로 첫 번째 일치 유형을 반환하며 실제 28일 활동 기록은 사용하지 않는다.

새 기능은 기존 신발 추천 결과에 붙이지 않는다. 별도 러너 분석 페이지와 별도 엔진으로 구현하고, 기존 삼국지 카드는 MVP 검증 전까지 변경하지 않는다.

## 사용자 흐름

```text
Garmin 연결 ─┐
             ├─> 28일 공통 요약 ─> 6개 내부 특성 ─> 공개 3축 ─> 36명 유사도 ─> 결과 1명
직접 입력 ───┘
```

공유물은 두 장이다.

1. 표지: 캐릭터, 칭호, 대표 수치, 신탁 한 줄
2. 분석 내지: 공개 3축, 판정 근거 2개, 강점, 맹점, 다음 14일 행동 1개

상세 웹 결과에는 28일 리듬과 전체 14일 가이드를 추가할 수 있지만, 공유 이미지의 지표와 캐릭터는 바꾸지 않는다.

## 공통 입력 모델

```ts
type RunnerGoal =
  | 'habit'
  | 'endurance'
  | 'record'
  | 'race'
  | 'health_fun';

type RaceGoal = {
  distanceKm: number;
  targetTimeMinutes: number;
};

type RunnerSnapshot28d = {
  windowDays: 28;
  totalDistanceKm: number;        // 필수
  runCount: number;               // 필수
  runDates?: string[];            // YYYY-MM-DD, 최대 28일 범위
  usualWeekdays?: number[];       // 0=일, 1=월 ... 6=토. 날짜가 없을 때만 사용
  averagePaceSecPerKm: number;    // 필수
  longestRunKm: number;           // 필수
  qualitySessionCount: number;    // 필수. 인터벌·템포·레이스, 없음은 명시적으로 0
  goal: RunnerGoal;               // 필수
  raceGoal?: RaceGoal;
};
```

### 입력 화면의 필수값

사용자가 결과를 만들기 위해 반드시 입력해야 하는 값은 여섯 개뿐이다.

| 화면 문항 | 상태 | 입력 예시 | 필요한 이유 |
|---|---|---|---|
| 최근 28일 총거리 | **필수** | `150km` | 전체 훈련량과 지구력 계산 |
| 러닝 횟수 | **필수** | `8회` | 1회 평균거리와 빈도 계산 |
| 평균 페이스 | **필수** | `5:30/km` | 목표 대비 훈련 압력 계산 |
| 최장거리 | **필수** | `30km` | 지구력과 장거리 성향 계산 |
| 강하게 뛴 횟수 | **필수** | `없음`, `2회` | 훈련 자극과 품질훈련 성향 계산 |
| 현재 목표 | **필수** | `대회 준비` | 캐릭터 점수의 목표 20% 계산 |
| 실제로 뛴 날짜 | 선택 | 달력에서 선택 | 회복 여유와 규칙성 정밀 계산 |
| 주로 뛰는 요일 | 선택 | `화·목·일` | 실제 날짜가 없을 때 간격 보완 |
| 목표 거리·기록 | 선택 | `마라톤 3:50` | 목표 페이스 보정 |

- 필수값에는 별표만 쓰지 않고 `필수` 문자를 함께 표시한다.
- 선택값에는 `선택 · 건너뛰어도 결과를 볼 수 있어요`라고 표시한다.
- 강하게 뛴 횟수는 빈칸을 0으로 바꾸지 않는다. 사용자가 `없음`을 직접 선택해야 한다.
- 필수 여섯 개가 유효하지 않으면 결과 버튼을 활성화하지 않고 해당 문항 바로 아래에 이유를 표시한다.
- 날짜·요일·목표 기록을 건너뛰어도 추가 확인창 없이 결과로 진행한다.

### 선택값을 건너뛴 경우

| 빠진 값 | 계산 방식 |
|---|---|
| 실제 날짜 | 주로 뛰는 요일이 있으면 한 주의 순환 간격을 사용 |
| 실제 날짜와 주로 뛰는 요일 | 평균 간격을 `28 / runCount`로 추정하고 `R` 상한을 70으로 제한 |
| 목표 거리·기록 | 목표 페이스 압력에 중립값 50 사용 |
| 실제 날짜가 없어 주별 규칙성을 계산할 수 없음 | 요일 패턴이 있으면 `C=75`, 없으면 `C=50` 사용 |

선택값 누락 여부와 입력 경로는 결과 카드에 표시하지 않는다. 단, 계산 객체에는 어떤 대체 규칙을 사용했는지 개발·테스트용 `fallbacksUsed` 배열로 남길 수 있으며 공유 결과에는 포함하지 않는다.

### 필수 검증

1. `totalDistanceKm > 0`, `runCount > 0`, `averagePaceSecPerKm > 0`이어야 한다.
2. `longestRunKm <= totalDistanceKm`이어야 한다.
3. `qualitySessionCount <= runCount`이어야 한다.
4. `runDates`가 있으면 중복을 제거하고 최근 28일 범위만 사용한다.
5. `runDates.length`와 `runCount`가 다르면 실제 날짜 수가 아니라 사용자가 명시한 `runCount`를 거리 평균에 사용하되, 간격 계산은 제공된 날짜만 사용한다.
6. `raceGoal`의 목표 페이스가 2:30/km 미만 또는 12:00/km 초과면 목표 페이스 보정에서 제외한다.
7. FIT·GPX·TCX나 Garmin에서 얻은 원본 활동은 이 모델로 축약한 뒤 영구 저장하지 않는다.
8. `qualitySessionCount`가 비어 있으면 0으로 변환하지 않고 필수 입력 오류로 처리한다.

## 모바일 입력·결과 화면 흐름

입력 구간은 일반적인 설문 카드가 아니라 **러닝 기록을 편집부에 건네는 팩트 시트**처럼 보이게 한다. 결과로 넘어가는 순간 같은 정보가 패션 매거진 표지로 변환되는 장면이 이 경험의 핵심이다.

### 0. 랜딩

- 화면의 대부분을 신화 속 러너 한 명의 에디토리얼 이미지와 큰 제호가 차지한다.
- 메인 문구: `지난 28일의 기록은 어떤 신화를 닮았을까?`
- 보조 문구: `거리와 페이스를 분석해 당신과 가장 가까운 신화 속 러너를 찾습니다.`
- 주 CTA: `내 러닝 신화 보기`
- CTA 바로 아래에 `약 2분 · 원본 기록 저장 안 함 · 공유 결과 7일 후 삭제`를 한 줄로 표시한다.
- 결과 예시 표지를 한 장만 살짝 노출하되 36명 전체 목록은 먼저 보여주지 않는다.

### 1. 입력 1/2 — 지난 28일 기록

한 화면에 네 값을 입력한다.

1. 최근 28일 총거리
2. 러닝 횟수
3. 평균 페이스
4. 최장거리

- 상단에는 얇은 진행선과 `1 / 2`만 표시한다.
- 숫자 키패드를 사용하고 단위 `km`, `회`, `/km`는 입력창 밖에 고정한다.
- 평균 페이스는 `분`과 `초`를 분리해 `5분 30초`처럼 입력하게 한다.
- 각 항목에 `필수`를 문자로 표시한다.
- 값이 비정상일 때만 항목 바로 아래에 한 줄 오류를 보여준다.
- 네 값이 유효해지면 하단 고정 버튼 `다음`을 활성화한다.

### 2. 입력 2/2 — 훈련 리듬과 목표

필수 두 값을 먼저 받는다.

1. 강하게 뛴 횟수: `없음 / 1회 / 2회 / 3회 이상`
2. 현재 목표: `습관 만들기 / 지구력 / 기록 단축 / 대회 준비 / 건강·즐거움`

그 아래에 `분석을 더 정교하게` 접이 영역을 둔다. 기본은 닫힌 상태이고 모두 선택값이다.

- 주로 뛰는 요일
- 실제로 뛴 날짜
- 목표 거리와 기록

접이 영역에는 `선택 · 건너뛰어도 결과를 볼 수 있어요`를 표시한다. 열었다가 아무것도 입력하지 않아도 추가 확인 없이 진행할 수 있다.

하단 고정 CTA는 `내 신화 결과 보기`다. 필수 여섯 값이 모두 유효할 때만 활성화한다.

### 3. 판정 전환과 광고

1. CTA를 누르는 즉시 브라우저 안에서 점수와 캐릭터를 계산한다.
2. 결과 저장이 성공하면 임의 공유 식별자와 7일 만료 시각을 만든다.
3. Google 비네트 광고가 가능한 경우에만 플랫폼의 자연스러운 전환 시점에 노출한다.
4. 광고가 로드되지 않거나 차단되어도 결과를 막거나 인위적인 10초 카운트다운을 만들지 않는다.
5. 광고 종료 후 표지의 이미지, 제호, 캐릭터 이름이 순서대로 나타나는 한 번의 진입 모션을 사용한다.

광고를 봤기 때문에 더 좋은 결과를 주는 것처럼 표현하지 않는다. 대기 문구는 `28일의 기록을 신화로 번역하고 있어요`로 고정한다.

### 4. 결과 — 앞표지

- 첫 화면은 밝은 아이보리·골드 계열의 9:16 패션 매거진 표지다.
- 신화 속 인물, 인물명, 신성 칭호, 대표 수치 하나, 신탁 한 줄만 보여준다.
- 대표 수치는 세 공개축 가운데 캐릭터 판정에 가장 크게 기여한 하나를 사용한다.
- 화면을 가볍게 위로 넘기거나 `분석 펼쳐보기`를 누르면 내지로 이동한다.
- 공유 CTA가 표지를 가리지 않도록 이미지 밖 하단 조작 영역에 둔다.

### 5. 결과 — 분석 내지

- 표지와 같은 아이보리·골드 편집 디자인을 유지하되 정보 밀도를 높인다.
- `지구력 / 훈련 자극 / 회복 여유` 세 점수
- 이 인물이 된 실제 기록 근거 두 개
- 강점 하나와 맹점 하나
- 다음 14일 행동 하나
- 하단에는 전체 14일 가이드와 신발 추천으로 이어지는 별도 CTA를 둘 수 있으나 공유 이미지에는 넣지 않는다.

### 6. 공유

주 CTA는 `인스타용 2장 저장`이다. 표지와 분석 내지를 같은 크기의 이미지 두 장으로 내려받는다.

보조 CTA는 다음 두 개다.

- `친구에게 링크 공유`: Web Share API를 우선 사용하고 지원하지 않으면 링크를 복사한다.
- `표지만 저장`: 표지 한 장만 내려받는다.

링크 공유 CTA 근처에는 `공유 링크는 7일간 열려요`를 짧게 표시한다. 공유 링크로 들어온 사람은 광고 없이 해당 결과를 보고, 하단의 `내 기록도 분석하기`로 새 분석을 시작한다.

### Garmin 연결이 추가될 때

- 연결 기능이 실제 사용 가능해지기 전에는 비활성 버튼이나 `준비 중` 카드를 랜딩에 노출하지 않는다.
- 연결 출시 후 랜딩 CTA 다음 화면에서 `Garmin으로 28일 기록 불러오기`를 주 선택지로, `직접 입력하기 · 약 2분`을 보조 선택지로 제공한다.
- Garmin에서 네 기록값을 불러온 뒤에도 입력 2/2에서 강한 훈련 횟수와 목표를 확인하거나 수정할 수 있게 한다.
- 어느 경로를 사용했는지는 결과와 공유 카드에 표시하지 않는다.

## 핵심 측정 이벤트

| 이벤트 | 발생 시점 |
|---|---|
| `runner_analysis_started` | 랜딩의 시작 CTA 클릭 |
| `runner_input_step_completed` | 입력 1/2 완료 |
| `runner_result_viewed` | 결과 표지가 실제 노출됨 |
| `runner_cover_saved` | 표지 한 장 저장 |
| `runner_carousel_saved` | 인스타용 두 장 저장 |
| `runner_share_started` | 링크 공유 또는 복사 시작 |
| `runner_shared_link_opened` | 다른 세션에서 공유 링크 열림 |

첫 MVP의 주 지표는 `공유 시작 세션 수 / 결과 표지를 본 고유 세션 수`다. 브라우저는 실제 SNS 게시 완료 여부를 안정적으로 알려주지 않으므로 게시 완료율을 약속하지 않는다. `2장 저장`과 `링크 공유`는 보조 지표로 각각 분리해 본다.

## 공통 보간 함수

모든 점수는 0~100으로 제한한다. 아래 앵커 사이 값은 선형 보간한다.

```ts
piecewise(value, [[input, score], ...]) => 0..100
```

| 하위 지표 | 앵커 `[입력, 점수]` |
|---|---|
| 28일 총거리 km | `[0,0] [40,25] [80,50] [120,70] [160,85] [220,100]` |
| 최장거리 km | `[0,0] [5,15] [10,35] [21.1,75] [30,95] [35,100]` |
| 1회 평균거리 km | `[0,0] [3,10] [8,45] [15,80] [22,100]` |
| 28일 러닝 횟수 | `[0,0] [4,20] [8,45] [12,70] [16,90] [20,100]` |
| 품질훈련 횟수 | `[0,0] [1,25] [2,45] [4,75] [6,100]` |
| 품질훈련 비율 | `[0,0] [0.1,30] [0.2,60] [0.3,85] [0.4,100]` |

## 여섯 개 내부 특성

사용자에게는 세 축만 보여주지만, 36명을 구분하려면 내부적으로 여섯 특성을 유지한다.

### 1. 지구력 `E`

```text
E = 총거리 45% + 최장거리 30% + 1회 평균거리 15% + 러닝 횟수 10%
```

절대 페이스는 지구력 점수에 넣지 않는다. 빠르기와 오래 달리는 능력을 같은 것으로 취급하지 않기 위해서다.

### 2. 훈련 자극 `S`

```text
S = 품질훈련 횟수 40%
  + 최장거리 점수 30%
  + 1회 평균거리 점수 20%
  + 목표 페이스 압력 10%
```

목표 페이스 압력은 `평균 훈련 페이스 / 목표 페이스` 비율로 계산한다.

| 비율 | 점수 |
|---|---:|
| 1.00 이하 | 100 |
| 1.05 | 85 |
| 1.15 | 55 |
| 1.30 | 25 |
| 1.50 이상 | 0 |

목표 기록이 없으면 목표 페이스 압력은 중립값 50을 쓴다. 평균 페이스는 능력 서열이 아니라 목표 대비 훈련 압력에만 사용한다.

### 3. 회복 여유 `R`

```text
R = 일반 러닝 간격 충분도 45%
  + 장거리 다음 러닝 간격 25%
  + 품질훈련 다음 러닝 간격 20%
  + 부하 대비 여유 10%
```

간격 충분도 앵커는 `[0일,0] [1일,35] [2일,75] [3일,90] [4일 이상,100]`이다.

`부하 대비 여유`는 다음처럼 계산한다.

```text
100 - (1회 평균거리 점수 × 0.50) - (총거리 점수 × 0.25)
```

- 품질훈련이 없으면 품질훈련 다음 간격은 100으로 둔다.
- 실제 날짜가 없고 요일 패턴만 있으면 한 주의 순환 간격으로 계산하고 최종 `R` 상한을 85로 둔다.
- 날짜와 요일 패턴이 모두 없으면 간격 관련 값은 중립값 50을 사용한다.
- `R`은 수면, HRV, 통증, 질병을 추정하지 않는다.

### 4. 규칙성 `C`

실제 날짜가 있으면 다음을 쓴다.

```text
C = 주별 러닝 횟수 안정성 50%
  + 반복 요일 일치율 30%
  + 최대 공백 억제 20%
```

- 주별 러닝 횟수 안정성: `100 - 100 × (주별 횟수 표준편차 / 주별 평균)`
- 반복 요일 일치율: 가장 자주 등장한 요일 템플릿에 포함되는 러닝 비율
- 최대 공백 억제 앵커: `[2일,100] [4일,90] [7일,65] [10일,35] [14일,0]`
- 요일 패턴만 있으면 `C=75`를 사용한다.
- 아무 일정 정보도 없으면 `C=50`을 사용한다.

### 5. 장거리 성향 `L`

```text
L = 최장거리 점수 60% + 1회 평균거리 점수 40%
```

### 6. 품질훈련 성향 `Q`

`qualitySessionCount / runCount`를 품질훈련 비율 앵커로 보간한다.

## 공개 지표

공유 카드와 웹 결과 모두 아래 세 숫자를 동일하게 사용한다.

| 표시명 | 내부값 | 의미 |
|---|---|---|
| 지구력 | `E` | 최근 28일 동안 감당한 거리와 장거리 경험 |

## 목표 정규화

직접 선택한 목표가 기본 목표다. 목표 기록이 있으면 보조 목표를 추가한다.

| 입력 | 목표 혼합 |
|---|---|

| 대회 준비, 목표 기록 있음 | `race 60% + record 40%` |
| 건강·즐거움 | `health_fun 100%` |

## 캐릭터 판정

각 캐릭터는 여섯 내부 특성의 목표 벡터와 주·보조 목표를 가진다.

```text
dataScore =
    similarity(E) × 18%
  + similarity(S) × 18%
  + similarity(R) × 18%
  + similarity(C) × 10%
  + similarity(L) × 8%
  + similarity(Q) × 8%

similarity(value, target) = 100 - abs(value - target)

goalAffinity =
  주 목표 일치 100
  보조 목표 일치 70
  그 외 30

finalScore = dataScore + weightedGoalAffinity × 20%
```

동점은 `dataScore`가 높은 캐릭터, 그다음 목표 친화도가 높은 캐릭터, 그다음 아래 표의 순서로 결정한다. 무작위 선택이나 사용자 식별자 해시는 사용하지 않는다.

## 결과 문장 생성 규칙

자유 생성형 AI를 호출하지 않는다. 점수와 캐릭터별 검수된 문장 조각을 조합한다.

### 판정 근거 두 개

1. 여섯 특성 중 캐릭터 목표값과 가장 가까우면서 사용자 점수가 60 이상인 특성을 첫 근거로 선택한다.
2. 두 번째 근거는 첫 근거와 다른 원시 데이터 계열에서 선택한다.
3. 가능한 근거 우선순위는 장거리, 총거리, 빈도, 품질훈련, 간격, 목표 순이다.
4. 근거에는 실제 숫자를 포함한다. 예: `1회 평균 18.8km`, `최장거리 30km`.

### 강점

사용자 점수가 70 이상이며 캐릭터 목표와 차이가 가장 작은 특성의 캐릭터별 문장을 사용한다.

### 맹점

다음 규칙 중 먼저 일치하는 하나만 사용한다.

1. `E >= 75 && Q < 25`: 긴 거리에 비해 훈련 변화가 적음
2. `S >= 80 && R < 50`: 강한 자극 사이의 여유가 적음
3. `C < 45`: 리듬이 자주 끊김
4. `L >= 80 && runCount < 10`: 한 번의 긴 러닝에 부하가 몰림
5. 모두 불일치: 캐릭터별 기본 맹점

### 다음 14일 행동

- 한 문장만 공유 카드에 노출한다.
- 현재 28일 평균 주간 횟수보다 주당 1회를 초과해 늘리지 않는다.
- 제안 장거리는 관측된 최장거리보다 길게 만들지 않는다.
- `R < 50`이면 거리나 속도를 늘리는 제안을 금지한다.
- 의료, 부상 예방, 치료 효과를 단정하지 않는다.
- 상세 일정은 사전 검수된 규칙표로 만들고 사용자별 자유 생성 문장을 사용하지 않는다.

## 기준 테스트 사례 A

사용자가 제공한 데이터다.

```text
28일 총거리: 150km
러닝 횟수: 8회
요일 패턴: 화·목·일
평균 페이스: 5:30/km
최장거리: 30km
인터벌·템포런: 0회
목표: 마라톤 3시간 50분
목표 페이스: 약 5:27/km
```

예상 계산 범위는 다음과 같다. 실제 구현에서는 소수점 계산 후 정수로 반올림한다.

| 값 | 예상 범위 | 근거 |
|---|---:|---|
| `E` | 82~84 | 150km, 30km 장거리, 1회 평균 18.75km |
| `S` | 55~58 | 품질훈련은 없지만 긴 1회 거리와 목표 페이스 근접 |
| `R` | 74~80 | 화·목·일 간격은 확보했지만 1회 부하가 큼 |
| `C` | 75 | 실제 날짜 없이 요일 패턴만 제공 |
| `L` | 92~94 | 30km 최장거리와 높은 1회 평균거리 |
| `Q` | 0 | 품질훈련 0회 |

예상 1순위는 `헤라클레스`, 차순위는 `오디세우스`, `아테나`다. 목표가 마라톤이어도 데이터 80%가 유지되므로 마라톤 이름과 직접 연결되는 페이디피데스가 자동 우승해서는 안 된다.

예상 공유 근거:

- `28일 동안 150km`
- `1회 평균 18.8km · 최장 30km`

예상 맹점:

- `긴 거리를 감당하는 힘에 비해 훈련 변화는 적은 편입니다.`

## 분포 검증

1. 각 캐릭터의 목표 벡터와 주 목표를 입력하면 자기 자신이 1순위가 되어야 한다.
2. 현실 범위의 합성 프로필 10,000개를 생성해 모든 36명이 최소 한 번은 선택되어야 한다.
3. 단일 캐릭터가 전체 결과의 10%를 넘으면 목표 벡터 또는 목표 친화도를 조정한다.
4. 다섯 목표 각각에서 최소 네 가문 이상이 결과에 등장해야 한다.
5. 입력값을 1% 바꿨을 때 상위 두 캐릭터의 점수 차이가 2점 이상이면 결과가 바뀌지 않아야 한다.

## 공유 결과 저장과 만료

1. 공유 링크에는 추측하기 어려운 임의 식별자를 사용한다. 예: `/runner-analysis/result/r8K2mP`.
2. 서버에는 캐릭터 ID, 공개 3축 점수, 판정 근거 두 개, 강점, 맹점, 결과 기준 월처럼 결과 재현에 필요한 익명 파생값만 저장한다.
3. 이름, Garmin 계정 정보, 연결 토큰, GPS 경로, 개별 운동 기록과 직접 입력 원본은 저장하지 않는다.
4. 공유 결과는 생성 시점부터 **7일 동안만** 열 수 있으며, 만료 후 자동 삭제한다.
5. 만료된 링크에는 개인정보나 이전 결과를 복구하지 않고 `결과가 만료되었어요. 최신 28일 기록으로 다시 분석해 보세요.` 안내와 재분석 버튼을 보여준다.
6. 광고·방문 분석 이벤트는 러닝 결과 저장소와 분리하고, 결과 식별자로 개인의 광고 행동을 결합하지 않는다.

1. 같은 `RunnerSnapshot28d`는 입력 경로와 무관하게 같은 세 점수와 같은 캐릭터를 반환한다.
2. 기준 사례 A는 `헤라클레스`를 반환하고 공개 지표가 문서의 예상 범위 안에 들어간다.
3. 모든 공개 점수는 0~100 정수다.
4. 36개 자기 벡터 테스트가 모두 자기 캐릭터를 반환한다.
5. 결과에는 실제 수치가 포함된 판정 근거가 정확히 두 개 존재한다.
6. 결과에는 강점 하나, 맹점 하나, 다음 14일 행동 하나가 존재한다.
7. 날짜가 없어도 요일 패턴으로 계산 가능하며, 둘 다 없을 때 예외 없이 중립값을 사용한다.
8. 원본 GPS, Garmin 계정 정보, 연결 토큰은 결과 객체에 포함되지 않는다.
9. 기존 `/recommend` 신발 추천 결과와 삼국지 카드 동작은 변경되지 않는다.
10. 단위 테스트와 `npm run build`가 통과한다.
11. 필수 여섯 개만 입력해도 결과를 생성할 수 있고, 세 선택 영역은 모두 건너뛸 수 있다.
12. 강한 훈련 횟수의 빈칸과 명시적인 `0회`를 서로 다른 상태로 처리한다.
13. 공유 결과는 생성 후 7일이 지나면 열리지 않고 자동 삭제된다.
14. 저장된 공유 결과만으로 이름, 계정, GPS 경로, 개별 운동 기록을 복원할 수 없다.

## 테스트 계획

| 계층 | 테스트 | 최소 개수 |
|---|---|---:|
| 단위 | 보간, 입력 검증, E/S/R/C/L/Q 계산 | 18 |
| 단위 | 목표 혼합, 유사도, 동점 처리 | 10 |
| 단위 | 설명 근거·맹점·행동 선택 | 10 |
| 분포 | 36명 자기 벡터 도달성 | 36 |
| 분포 | 합성 프로필 10,000개 편향 검사 | 1 |
| 통합 | 직접 입력과 연결 입력의 동일 결과 | 3 |
| E2E | 입력 → 광고 전환 → 표지 → 분석 내지 → 공유 | 1 |

- 36명 최종 이미지 생성
- 신발 추천 로직 변경

## 되돌리기

새 엔진과 페이지는 기존 `/recommend`와 분리한다. 문제가 있으면 새 라우트와 `src/lib/runner-analysis/`만 제거하면 기존 신발 추천 기능에 영향 없이 되돌릴 수 있다.
