# 첫 30km 시제품 — 검증 및 다음 작업

## 최종 연출 개선 — 2026-09-11

### 감상에서 확인한 문제

- 기존 390×844 모바일 WebGL 화면에서 23km 뒤로 한강 사진이 잔류하고 경로 선이 본문을 가로질렀다.
- 기존 선형 투명도 계산은 장면 중간에서 두 본문의 합산 opacity가 0.25까지 내려가 읽을 시간이 짧았다.
- 28km 사진은 하늘이 화면 대부분을 차지하고 인물이 본문과 검은 그라데이션 뒤에 가려졌다. 사진에 보이는 두 사람을 모두 러너로 단정할 근거도 없어서 대체 텍스트를 수정했다.
- 모션을 꺼도 필름 그레인 CSS 애니메이션이 계속 실행됐다.
- 크레딧 완료 후 visibility 이벤트가 finished 애니메이션을 pause 상태로 바꾸어 다시 이어 재생할 수 있는 코드 경로가 있었다.

### 적용한 연출

- `story-timeline.ts`: 5개 장면별 읽기 구간과 전환 구간을 분리했다. 진행 수치는 이야기의 흐름이며 실제 GPS 위치나 시간의 보간이 아니다.
- 23km: 어두운 입체 23, 좁아지는 바닥 선, 가까운 카메라와 낮아진 흰 조명. 인용문은 세 줄로 유지한다.
- 28km: 빛·입자·경로를 물리고 사람을 중심으로 자른 사진 프레임과 감사 문구에 집중한다. 사진이 28km 지점에서 촬영됐다는 주장은 하지 않는다.
- 30km: 카메라가 물러나고 조명이 밝아지며 입체 숫자가 정면에 가깝게 놓인다.
- 그레인은 움직이지 않는 작은 타일로 줄였다. 스크롤 반응은 시간 차이를 반영하며, 정지·비가시 상태에서 WebGL의 연속 렌더링을 멈춘다.
- 모션 제어를 스크롤 중에도 접근할 수 있게 헤더를 고정했다.
- 크레딧 32초, 완료 후 감사 문장 유지. 모달 사진 이동 중 스크롤 잠금이 재설정되지 않게 했고 닫을 때 원래 사진 버튼으로 초점을 돌린다.
- 실제 인물 사진이 있는 티켓과 1080×1350 PNG 저장을 추가했다. 저장 코드는 버튼을 누를 때만 불러온다.

### 후속 모델용 브라우저 검증 지시

개선 전 모바일 다섯 장면 중 오프닝·23·28·30을 캡처하고 직접 확인했다. 개선 후 첫 Ego Lite 검사 공간은 모델 전환 뒤 사라졌고, 새 공간 생성 권한은 거절됐다. 이후 Codex 인앱 브라우저로 390×844 검증을 진행했다.

### 개선 후 통과 항목

- 390×844에서 0 / 28 / 49 / 72 / 95% 이야기 위치 확인. 오프닝·한강·23·28·30 장면 표시는 각각 의도한 챕터로 전환됐고 모든 지점에서 가로 넘침이 없었다.
- 1440×900에서 28km 장면을 추가 확인. 사진과 본문이 좌우로 분리되고 거리·챕터가 `28.00`, `03 / 28 KM`로 수렴했으며 가로 넘침이 없었다.
- 정지 후 완주 장면은 `30.02`, `04 / MY FIRST 30K`로 수렴했다. 나머지 장면의 계산된 opacity는 0, visibility는 hidden, pointer-events는 none이었다.
- 23km의 어두운 입체 숫자와 인용문, 28km 사진 프레임과 감사 문구, 30km의 밝은 입체 숫자를 모바일 캡처로 직접 확인했다.
- 사진첩 첫 사진 열기 → 다음 사진 → 닫기 통과. 두 번째 캡션이 표시됐고 닫은 뒤 첫 사진 버튼으로 초점이 복귀했으며 dialog는 닫혔다.
- 크레딧 화면 진입 시 자동 재생, 일시정지, 재개 버튼 상태 전환 통과.
- 티켓 저장 버튼 실행 후 `기념 티켓을 저장했어요.` 상태 확인. 인앱 브라우저가 canvas object URL 다운로드 이벤트를 검사 API에 전달하지 않았고 사용자 Downloads 폴더에도 노출하지 않아, 생성된 PNG 파일의 픽셀 크기·한글 렌더링은 직접 열어 확인하지 못했다.
- 개선 후 `npx tsc --noEmit`, 타임라인 단조 증가·5개 정지점 검사, `git diff --check` 통과.
- 개선 후 `npm run build` 통과: 1,016개 정적 페이지와 sitemap 생성 완료. `/saturday/first-30k` First Load JS 119kB.

### 남은 검증 항목

1. 375×667과 1440×900의 나머지 0 / 28 / 49 / 95% 이야기 위치를 확인한다. 기준 스크롤은 `journey.offsetHeight - stage.clientHeight`이다. 각 장면이 충분히 읽히고 이전 사진·숫자가 남지 않아야 한다.
2. 23km의 3D 숫자와 인용문, 28km 사진의 인물과 감사 문장이 겹치지 않는지 캡처한다. 30km 완료 시 거리 표시가 30.02에 도달해야 한다.
3. 장면 사이를 느리게/빠르게/역방향으로 스크롤한다. 가로 넘침, 텍스트 소실 구간, 점멸, 무대 이탈이 없어야 한다. 정지 뒤 추가 렌더링이 수렴하는지 확인한다.
4. 모션 끄기/다시 켜기, OS reduced-motion, WebGL 생성 실패와 context loss에서 정적 사진·본문·크레딧이 모두 읽혀야 한다.
5. 갤러리의 이전 버튼과 Escape 닫기를 추가 확인한다.
6. 경로 영상의 실제 재생과 탐색을 확인한다. 크레딧 완료/탭 비가시/다시 보기/마지막 장면 링크를 확인한다. 완료 후 스크롤로 돌아와도 자동 재시작하면 안 된다.
7. 일반 Chrome 또는 Safari에서 티켓 저장 뒤 실제 PNG를 열어 1080×1350 크기, 한글 폰트, 인물 크롭, 숫자와 KM 간격을 확인한다. iOS Safari의 사진 저장 흐름도 별도로 확인한다.
8. 실기기 프레임 속도·발열은 에뮬레이션과 구분해 기록한다. 커밋·배포는 이번 작업 범위에 포함되지 않는다.

## 발견한 문제와 남은 재검증

- 스크롤 후 sticky 무대가 화면을 벗어나 검은 화면만 보이는 문제를 브라우저에서 확인했다.
- 상위 body의 overflow가 `hidden auto`라서 실제로 스크롤하지 않는 sticky 컨테이너가 되는 것을 확인했다.
- 페이지의 로컬 클래스가 존재할 때만 body의 overflow를 `clip visible`로 바꾸는 CSS를 적용했다. CSS Modules에서는 전부 global인 selector를 사용할 수 없어 `:global(body):has(.story)`로 범위를 지정했다.
- 수정 후 브라우저에서 WebGL을 다시 켜고 한강→23→28→30 네 장면을 확인했다. 모든 지점에서 sticky 무대의 top은 0이었고, 해당 장면 opacity는 0.97 이상이었다. 거리 표시는 14.80→22.88→27.93→29.99로 진행됐다.
- 다음 확인 대상: 갤러리 확대/닫기/초점 복귀, 경로 영상 실제 재생, 크레딧 pause/replay/skip, WebGL context loss 대안.
- 실물 휴대폰 검증은 수행하지 않았다. 현재 기록을 완전한 모바일 QA 통과로 해석하지 않는다.
