# allrunabout 홈 리디자인 설계

작성일 2026-07-31 · 대상 브랜치 `redesign-b` · 상태 승인됨

---

## 1. 목적과 범위

홈페이지를 전면 재설계해 allrunabout을 "한국 러너 기준으로 러닝화를 정리하는 플랫폼"으로 인식시키고,
맞춤 추천·상세·비교·베스트·블로그로의 이동을 강화한다.

홈의 임무는 자체 광고 수익이 아니라 **순회 허브**다. 홈은 전체 조회의 10.5%를 차지하지만
직접 광고 수익은 3.7%이고, 신발 상세가 전체 수익의 60~70%를 차지한다.
따라서 홈의 성과는 하위 페이지 이동률과 홈 경유 세션 전체 수익으로 판단한다.

**포함**: 홈 전체 정보구조 · 상단 내비 · 키네틱 히어로 · 고민별 탐색 · 추천 설명 · 신뢰 지표 ·
필터와 러닝화 인덱스 · 재방문 이어보기 · 기존 광고 슬롯 1개 · 에디토리얼 · 최종 CTA ·
반응형 · 접근성 · 성능 · SEO · GA4 이벤트 · 전역 팔레트 토큰 조정

**제외**: 마라톤 지도와 마라톤 페이지 구조 · 상세/비교/베스트/블로그 레이아웃 재설계(후속 단계) ·
새 추천 알고리즘 · 신규 AdSense 슬롯 발급

### 1.1 진행 순서

바로 프로젝트 코드를 수정하지 않는다.

1. 설계 문서 수정 → 2. 데스크톱 전체 시안 → 3. 모바일 전체 시안 →
4. 검토 및 승인 → 5. 실제 코드 구현 → 6. 성능·접근성·GA4·광고 검증

**시안 승인 전에는 프로젝트 구조를 대규모로 변경하거나 배포하지 않는다.**

## 2. 확정된 전제

착수 전 지시서와 현재 코드가 충돌하는 지점을 조사해 확정했다. 아래 설계는 전부 이 전제 위에 있다.

| # | 쟁점 | 확정 | 근거 |
|---|---|---|---|
| 1 | 팔레트 적용 범위 | `redesign-b` 위에서 작업 | 잉크+시그널이 이미 89개 파일에 전역 이식됨(미배포). 홈만 바꾸면 톤이 갈라짐 |
| 2 | 재방문 이어보기 | 기록 훅까지 구현 | `saved-shoes.ts`(찜) 외에 최근 본/비교/추천 기록 코드가 없음 |
| 3 | 러닝화 인덱스 | 화면 16행 + 나머지는 `<details>` | 현행 122켤레 전체 렌더로 41,722px |
| 4 | 전체 목록 페이지 | **신규 생성 안 함** | 필터를 쓰는 목록 경로가 `home-content.tsx` 하나뿐 — 전체 목록 페이지가 곧 홈 |
| 5 | 고민별 탐색 목적지 | `/best/*` 큐레이션 | 6개 고민이 전부 실존 slug에 매핑됨. 고RPM 페이지로 세션 이동 |
| 6 | 고민 항목 수 | 6개 (§16의 5개 + 무릎 부담) | 무릎은 검색 수요가 크고 `/best/knee-protection`이 실존 |
| 7 | 히어로 모션 빈도 | 세션당 1회 | 홈은 1인당 3~4회 경유하는 순회 허브 |
| 8 | 신발 와이어프레임 | 3켤레 이상 조합 기반 중립 SVG 실루엣 | 손으로 쓴 SVG path 3회 실패(배·카누 형태). 특정 모델 단일 추출 방식은 운영자가 철회함. 4절 참조 |
| 9 | 배포 단위 | 팔레트 전체 + 홈 구조 | 토큰만 바꿔도 89파일이 함께 변함. 톤 불일치 기간을 만들지 않음 |
| 10 | 확산 로드맵 | 상세 → 베스트/vs → 기능 → 콘텐츠 | 수익 기여도 순 |

### 4번이 설계에 미친 영향

`/shoes`를 신규 생성하지 않으므로 **필터는 홈에 그대로 남는다**(지시서 §20 원안 충족).
인덱스는 정적 HTML에 122행을 전부 렌더하되 16행 초과분을 `<details>`로 접는다.

- 내부링크 122개가 정적 HTML에 그대로 남아 SEO 손실 없음
- 화면상 스크롤은 16행 분량
- 새 URL 0개
- `<details>`라 자바스크립트 없이도 펼쳐지고 크롤러가 내부를 읽음

## 3. 팔레트 전환

승인된 Warm Performance는 `redesign-b`에 이미 적용된 잉크+시그널의 미세 조정판이다.

```css
:root {
  --paper:       #F7F4ED;   /* redesign-b: #FCFBF9 */
  --paper-soft:  #EFEAE0;   /* redesign-b: #F7F5EE (--bg-warm-alt) */
  --surface:     #FFFFFF;   /* 동일 */
  --ink:         #17150F;   /* 동일 */
  --ink-soft:    #6E6A5E;   /* redesign-b: #5F5B4E (--secondary) */
  --line:        #D9D4C8;   /* redesign-b: #E3E0D6 (--border) */
  --signal:      #FF4D00;   /* 동일 */
  --signal-soft: #FFE7DB;   /* redesign-b: #FFF0E8 (--accent-soft) */
  --signal-dark:    #C73800;
  --positive:       #2F7D5A;
  --warning:        #C98112;
  --dark-soft:      #28241D;
  --light-on-dark:  #F7F4ED;
}
```

`src/app/globals.css`의 값 5개를 조정하면 89개 파일이 함께 전환된다.
`tailwind.config.ts`가 `sky`/`slate` 스케일을 오버라이드해둬서 raw 클래스를 쓰는 파일도 코드 수정이 필요 없다.
스케일 값(`sky.50`~`sky.950`, `slate.50`~`slate.950`)은 새 `--paper`/`--line`에 맞춰 함께 미세 조정한다.

### 색 사용 규칙

- 밝은 배경 70~80% / 잉크 영역 20~30% / 시그널은 제한적
- **오렌지 솔리드 채움은 페이지 전체에서 CTA 2곳(히어로·최종 밴드)에만 허용**한다.
  나머지 오렌지 용법은 선·텍스트·테두리 강조뿐이라 CTA가 유일하게 면으로 튀어나온다.
- 다크 영역은 최종 CTA 밴드 한 곳. 전체 세로 픽셀 대비 22% 이하
- 새 유채색 추가 금지
- **`prefers-color-scheme` 기반 자동 다크 테마는 홈에서 제거**한다(`prefers-reduced-motion`은 유지)

### 타이포

- 한글 제목·본문·UI: Pretendard 또는 시스템 산세리프. 대형 제목은 800 이상
- 수치·라벨·상태: mono. **한글 본문에는 쓰지 않는다**
- `word-break: keep-all`, 제목에 `text-wrap: balance`, 숫자 정렬에 `tabular-nums`
- 한글 세리프 금지

## 4. 히어로

### 4.1 구성과 제약

- 데스크톱 최대 100svh, 모바일 65~75svh(강제하지 않음)
- 스크롤 가로채기·핀 스크롤 금지. CTA는 연출 중에도 즉시 클릭 가능
- 자동 연출 4.5초(모바일 2.4초) 후 종료. 세션당 1회(`sessionStorage`)
- 주인공은 특정 제품이 아니라 브랜드와 분석 시스템

텍스트는 지시서 원문 그대로 사용한다. 키커 `KOREAN RUNNER FIT INDEX`,
메인 카피 `감으로 고르지 / 않는다.`(둘째 줄만 시그널), 보조 문구, 주요 CTA `약 1분 · 9문항 맞춤 추천`,
CTA 보조 정보, 보조 CTA `고민별로 찾아보기`(고민별 탐색으로 스크롤).

### 4.2 러닝 에너지 — 사선 트랙

분석 60 : 에너지 40의 인상을 만들기 위해 수평 중심 구성을 사선으로 바꾼다.

- **트랙 레인**: 배경에 `-9°` 평행선 5줄. 아래로 갈수록 진해져 원근을 만든다
- **데이터 기준선**: 4줄을 같은 `-9°`로. 각 선 끝에 시그널 캡
- **라벨 진입**: 왼쪽에서 사선 방향으로 흘러들어와 기준선에 정렬.
  기울어진 좌표계 안에 두되 라벨 자체는 역회전시켜 텍스트를 수평으로 유지한다(가독성)
- **속도선**: 실루엣 힐 뒤로 뻗는 시그널 선 3줄
- **스타트 라인**: 좌측에 얇은 사선 1줄 + `START` 라벨

카피 영역에도 사선 요소를 최소한으로 둔다(키커 앞 짧은 시그널 선, 로고 옆 수직선).

### 4.3 모션 타임라인

| 구간 | 장면 | 내용 |
|---|---|---|
| 0.0–0.8s | 복잡한 시장 | 희미한 신발 윤곽 위로 제품명 4개 + 수치 라벨 8개가 흩어진 채 등장. 어느 제품도 가장 크지 않다 |
| 0.8–1.8s | 같은 기준으로 정렬 | 수치가 무게·드롭·발볼·용도 4개 기준선으로 이동. 제품명은 여기서 사라진다 |
| 1.8–2.8s | 와이어프레임 형성 | 러닝화 윤곽선이 왼쪽에서 오른쪽으로 드러난다(전진 방향과 동일) |
| 2.8–3.6s | 한국 러너의 발 | 점선 발 윤곽 중첩 + 발볼 계측 틱 3개 |
| 3.6–4.5s | 적합 영역 → CTA | 적합 영역 강조 → 신발 4~8px 전진 → CTA 화살표 반응 |
| 이후 | 정지 | 데스크톱 `pointer:fine`에서만 2~6px 시차. **카피와 CTA는 움직이지 않는다** |

**오렌지 적합 영역 불투명도** — 최대 0.28~0.36, 최종 정지 0.16~0.22.
적합 영역이 CTA보다 강하게 보이면 안 된다.

**금지** — 러너 영상 · 선수 대형 사진 · 신발 회전 · 신발 점프 · 네온 잔상 ·
글리치 · 무한 반복 · CTA와 메인 카피 이동 · 특정 글로벌 스포츠 브랜드 캠페인 복제

제품명 라벨은 실존 모델만 쓴다(`NOVABLAST 6` `PEGASUS 42` `SC ELITE V5` `GEL-KAYANO 33` — 전부 DB 확인됨).
최종 잔류 라벨은 4개(`249g` `8mm DROP` `WIDE 76mm` `DAILY`).

### 4.4 중립 러닝화 실루엣

특정 모델을 trace하지 않는다. **데일리·쿠션화·레이싱 3켤레 이상의 외곽 특징을 조합해
중립적인 러닝화 SVG로 재정리**하고, 디자인 단계에서 정적 path로 확정한다.

조합 구조: A에서 힐 구조 / B에서 발등·갑피 라인 / C에서 앞코·미드솔 전개

**반드시 남길 특징** — 러닝화로 인지되는 측면 형태 · 약간 올라온 힐 ·
자연스럽게 낮아지는 발등 라인 · 러닝화 특유의 앞코 · 미드솔 볼륨 · 전진 방향

**제거할 요소** — 브랜드 로고 · 신발끈 디테일 · 메시 패턴 · 아웃솔 러그 ·
브랜드 고유 패널 · 특정 모델의 독특한 힐 구조 · 카본 플레이트 컷아웃 · 과도한 로커 곡선

**구현 제약** — 런타임 이미지 분석 금지 · inline SVG 또는 경량 SVG asset ·
채워진 제품 이미지가 아니라 외곽선과 최소한의 내부선만 · allrunabout 전용 시각 자산으로 관리

**승인 조건 6가지** — ① 첫눈에 러닝화로 보인다 ② 특정 브랜드·모델이 떠오르지 않는다
③ 배·카누·구두처럼 보이지 않는다 ④ 기술 도면 같되 지나치게 차갑지 않다
⑤ 발 윤곽을 겹쳐도 자연스럽다 ⑥ 모바일에서도 형태를 인지할 수 있다

### 4.5 히어로 비주얼 비중

카피·타이포 35~40% / 숫자·데이터 25~30% / 선·실루엣 20~25% / 실제 제품 이미지 5~10%.
히어로에 채워진 제품 사진은 0장이다. 실제 썸네일은 인덱스 행에서만 쓴다.

### 4.6 첫 1초 인지

사용자는 모션이 끝날 때까지 기다리지 않아도 러닝화 서비스임을 알아야 한다.
실루엣을 모션 후반에 등장시키지 않는다.

- 첫 프레임부터 신발 외곽을 **불투명도 10~15%로 노출**
- 모션이 진행되며 외곽선과 미드솔 선이 점차 선명해짐
- 최종 장면에서 발 형태 중첩 + 적합 영역 + CTA

**검증**: 3초간 히어로를 본 사용자가 ① 어떤 종류의 사이트인가 ② 무엇을 도와주는가
③ 먼저 눌러야 할 버튼은 무엇인가에 답할 수 있어야 한다.

### 5.1 고민별 탐색 (6개)

### 5.2 러닝화 인덱스

정적 HTML에 122개 링크를 전부 유지하되, `전체 보기` 시 106행이 한꺼번에 펼쳐지지 않게 한다.

기본 표시: 데스크톱 16 / 모바일 12
점진 확장: 기본 → +24 → +24 → 나머지 전체
버튼: `러닝화 24개 더 보기` / 마지막 단계는 `전체 러닝화 보기`

- HTML에는 전체 122개 링크 유지
- JavaScript 없이도 `<details>`로 전체 접근 가능
- JavaScript 활성 시 점진 노출
- **필터는 전체 122개를 대상으로 동작하고, 필터 결과는 노출 제한보다 우선한다**
  (결과 8개면 8개 전부 표시, 40개면 16개 표시 후 점진 확장)
- 결과 수는 `aria-live`로 안내

기본 정렬은 카테고리 균형(데일리 4 · 쿠션 3 · 입문 3 · 레이싱 2 · 안정 2 · 트레일 2).
행은 7칸 그리드: 썸네일 · 브랜드+모델 · 한 줄 결론 · 용도 · 무게 · 가격 · 데이터 상태.
(구현 시 그리드 칸 수와 자식 요소 수를 반드시 일치시킬 것 — 시안에서 6칸으로 잡아 배지가 다음 줄로 밀리는 버그가 있었다.)

필터 칩: 전체 · 카테고리 6종 · 와이드 출시 · 20만원 이하.

데이터 상태 배지는 6종(`공식 정보` `외부 랩 확인` `리뷰 종합` `직접 착화` `추정치` `갱신 대기`)을 쓰고
`외부 랩 확인`만 시그널 색으로 강조한다. 색만으로 구분하지 않고 텍스트를 함께 둔다.

> 클래스명 주의: 배지에 `.lab`을 쓰지 말 것. 히어로 데이터 라벨의 `.lab`과 충돌해 배지가 사라진다.

## 6. 반응형

데스크톱 축소가 아니라 모바일을 별도 설계한다.

| 항목 | 데스크톱 | 모바일 (≤900px) |
|---|---|---|
| 히어로 높이 | 최대 100svh | 65~75svh, 강제 없음 |
| 모션 길이 | 4.5s | 2.4s |
| 라벨 수 | 12개 → 4개 잔류 | 4개(잔류 라벨만) |
| 정렬 연출 | 기준선 4개로 이동 | 생략 — 등장 후 바로 최종 배치 |
| 스타트 라인·속도선·기준선 태그 | 표시 | 숨김 |
| 마우스 시차 | 2~6px | 없음 |
| 고민별 탐색 | 3열 × 2행 | 1열 6행 |
| 인덱스 | 16행 / 7칸 | 12행 / 3칸 압축(썸네일·모델·가격 + 무게·상태) |
| 필터 | 칩 인라인 | 바텀시트(ESC 닫힘, 포커스 트랩) |
| 저사양 기기 | — | 정적 inline SVG로 대체 |

**모바일 첫 화면**에 키커·메인 카피·보조 문구·주요 CTA가 스크롤 없이 들어간다.
비주얼은 CTA 아래에 두되 **실루엣 기준 약 15% 확대**하고 위 여백을 줄여 러닝화 단서가 빨리 보이게 한다.

확대는 컨테이너 폭만 키우면 라벨과 신발이 좌우로 잘리므로 두 값을 나눠 적용한다:

| | 데스크톱 | 모바일 | 실루엣 실폭 |
|---|---|---|---|
| 비주얼 컨테이너 | 100% | 106% (`margin-left: -2%`) | — |
| 실루엣 위치·폭 | `left 26% / width 70%` | `left 22% / width 76%` | — |
| **합산 배율** | `1.00 × 0.70 = 0.70` | `1.06 × 0.76 = 0.806` | **+15%** |

여백은 `aspect-ratio`를 `560/400`에서 `560/280`으로 줄이고 `margin-top: -10px`를 줘 CTA에 붙인다.
컨테이너를 118%까지 키우면 라벨 왼쪽과 신발 앞코가 화면 밖으로 나가므로 이 조합을 넘기지 않는다.

확인 폭: 1440 / 1280 / 1024 / 768 / 430 / 390 / 360.

## 13. 배포 계획과 확산 로드맵

| 4 | 비교 / 추천 | 기능 페이지 |
| 5 | 블로그 / 마라톤 | 콘텐츠 |

각 단계 배포 후 GA·AdSense로 가드레일을 확인하고 다음 단계로 넘어간다.

### 확산할 것과 홈에 남길 것

**확산한다** — 데이터 상태 배지(홈에서 "외부 랩 확인"이라 해놓고 상세에 표기가 없으면 신뢰 체계가 어긋난다) ·
mono 수치 표기와 `tabular-nums` · 플랫 조판(그림자 0, radius 2px 이하) · 행 기반 목록(나열형 페이지)

**홈에 남긴다** — 사선 트랙 · 키네틱 모션 · 실루엣 와이어프레임.
홈은 관문이라 강한 인상이 필요하지만 상세·비교는 읽고 판단하는 도구라 조용해야 한다.
상세 배경에 사선 트랙을 깔면 수치 읽기를 방해한다. 타협이 아니라 의도된 분리다.
