# 블로그 썸네일 정합·스타일 설계

**작성일**: 2026-08-02
**범위**: 블로그 전면 개편의 **서브프로젝트 1/3** — 썸네일

## 1. 문제

블로그 카드가 "안 맞아" 보인다. 원인은 셋이고, 스타일보다 **규약 부재**가 먼저다.

### 1.1 하나의 자산이 네 곳에서 각기 다른 비율로 잘린다

썸네일은 전부 OG 규격(1200×630 = **1.905**)으로 만드는데, 소비하는 표면이 제각각 자른다.

| 표면 | 프레임 | 비율 | 잘림 | 사라지는 것 |
|---|---|---|---|---|
| 홈 에디토리얼 lead | `aspect-ratio: 3/2` | 1.500 | **가로 27.0%** | 데이터 우측 열 통째로 |
| 블로그 카드 | `aspect-[16/9]` | 1.778 | 가로 7.1% | 좌우 여백 |
| 상세 히어로 | `aspect-[21/9]` | 2.333 | **세로 22.5%** | 킥커·각주 |
| OG 공유 | 원본 | 1.905 | 없음 | — |

`object-cover`는 프레임이 이미지보다 좁으면 가로를, 넓으면 세로를 잘라낸다.
어느 표면도 자산의 native 비율과 맞지 않는다.

### 1.2 카드 배지가 이미지의 킥커를 덮는다

`blog-card.tsx`가 `absolute left-4 top-4`에 흰색 카테고리 알약을 덧그린다.
썸네일 템플릿은 **바로 그 자리에 킥커 문구**(대시 + 소제목)를 갖고 있어 앞부분이 가려진다.

```
원본:  ▬ 공급망 추적 · 국내 미보도
화면:  [뉴스]적 · 국내 미보도
```

221편 전부에 해당한다. 카테고리는 이미지 킥커와 의미가 겹치기까지 한다.

### 1.3 스타일이 사이트 팔레트에서 이탈했다

홈 리디자인으로 사이트는 잉크+시그널(종이 `#F7F4ED` · 잉크 `#17150F` · 오렌지 `#FF4D00`)로
정리됐다. 썸네일은 네이비·골드·퍼플·그린의 어두운 그라디언트다. 색이 카테고리와 대응하지도
않아 의미를 나르지 않으면서 그리드만 산만하게 만든다.

밀도도 카드에 안 맞는다. 킥커·제목·부제·데이터 3행·각주의 **5단 구성**은 1200px에서 읽으라고
만든 것이고, 카드 실제 렌더 크기는 **350×197**이다. 제목 아래는 전부 판독 불가한 질감이 된다.

### 1.4 부수 결함

- **비율 이탈 6건** — 209/215가 1.905인데 나머지가 어긋난다. 그중 **2건은 세로형**(0.700 · 0.750)이라 어떤 가로 프레임에서도 깨진다
- **외부 Unsplash 4건** — 자체 제작 스타일과 이질적이고 외부 호스트에 의존한다
- **신발 제품샷 전용 4건** — `/images/shoes/...`를 그대로 썸네일로 쓴다

## 2. 목표

1. 네 표면 어디서도 썸네일이 잘리지 않는다
2. 카드 배지가 이미지 내용을 가리지 않는다
3. 트래픽 상위 글의 썸네일이 사이트 팔레트와 같은 언어를 쓴다

**목표가 아닌 것**: 탐색 축 재설계(서브프로젝트 2) · 상세 페이지 개편(3) · 221편 전량 재생성.

## 3. 근거 데이터

GA4 최근 28일, `/blog/` 경로 한정. 총 조회 1565 (사이트 전체 9673의 16%).

| 범위 | 커버리지 |
|---|---|
| 상위 5편 | 27.3% |
| 상위 10편 | 38.3% |
| 상위 20편 | 53.5% |
| **상위 30편** | **64.5%** |
| 상위 50편 | 78.8% |

유입된 글 158편 / 221편 — **63편(29%)은 28일간 조회 0**이다.

상위 30편이 자산의 14%로 조회의 64.5%를 덮는다. 여기서 재생성을 끊는다.

> ⚠️ 정직하게 적어 둔다: `/blog` 인덱스 자체는 28일 조회 **125**에 불과하다.
> 썸네일의 실제 노출은 대부분 **상세 페이지의 관련글 모듈 · 홈 에디토리얼 · OG 공유**에서
> 일어난다. 카드 그리드만 보고 판단하면 효과를 과대평가하게 된다.

## 4. 설계

### 4.1 1층 — 정합 규약 (자산 재생성 0장)

**모든 표면을 자산의 native 비율 `1200/630`으로 통일한다.**

OG 비율은 소셜 플랫폼이 고정한 값이라 우리가 못 바꾼다. 그러니 내부 표면이 그쪽에 맞춘다.
반대로 하면 공유 카드가 깨진다.

| 파일 | 변경 |
|---|---|
| `src/components/blog/blog-card.tsx` | `aspect-[16/9]` → `aspect-[1200/630]` (썸네일 없는 폴백도 동일하게) |
| `src/app/(detail)/blog/[slug]/page.tsx` | 히어로 `aspect-[21/9]` → `aspect-[1200/630]` |
| `src/components/home/editorial-section.module.css` | `.leadImg { aspect-ratio: 3/2 }` → `1200/630` |

통일하면 **잘림이 0이 되어 안전영역 규약 자체가 불필요해진다.** 크롭을 전제한 설계보다
단순하고, 레거시 191장에도 그대로 적용된다.

홈 lead는 이미지가 낮아져 텍스트가 위로 올라온다. 엊그제 배포한 홈을 건드리는 변경이므로
스크린샷으로 확인한다(§6).

**카테고리 배지를 이미지 밖으로 옮긴다.**

`blog-card.tsx`의 `absolute left-4 top-4` 오버레이를 제거하고, 카테고리를 이미지 아래
텍스트 블록(날짜·읽기시간이 있는 줄)에 넣는다.

- 충돌이 원천적으로 사라진다 — 이미지 위에 아무것도 그리지 않는다
- 킥커가 없는 8장(Unsplash 4 + 제품샷 4)에서도 카테고리가 정상 표기된다
- 색만으로 구분하지 않는다 — 텍스트 라벨을 유지한다

### 4.2 2층 — 새 템플릿 (상위 30편)

**팔레트**: 종이 `#F7F4ED` 바탕 · 잉크 `#17150F` 제목 · 보조 `#6E6A5E` · 규칙선 `#D9D4C8` ·
시그널 `#FF4D00`은 **대시와 강조에만**.

> 대비 주의: `#FF4D00`은 밝은 배경 위 소형 텍스트에 쓰지 않는다(3.03). 강조 텍스트가 필요하면
> `--signal-dark`(4.79)에 해당하는 값을 쓴다. 썸네일은 이미지라 자동 검사에 안 걸리므로
> 육안으로 확인한다.

**구성 — 5단에서 3단으로 줄인다.**

```
┌──────────────────────────────────┐  1200×630
│                                  │
│  ▬ 소재 해설 · 2편                │  킥커 (오렌지 대시 + 잉크 텍스트)
│                                  │
│  플레이트, 대체 뭘 하나            │  제목 (최대 2줄, 잉크, 굵게)
│                                  │
│  카본이 만드는 건 에너지가         │  부제 (1줄, 보조색)
│  아니라 지렛대입니다               │
│  ─────────────────────           │  규칙선
│  출처 한 줄        allrunabout.com │  각주 (작게)
└──────────────────────────────────┘
```

데이터 3행은 뺀다. 카드 350px에서 읽히지 않아 질감으로만 남고, 그 질감이 그리드를 어지럽히는
주범이다. 제목이 카드에서 하는 일을 데이터가 방해한다.

**한글에 mono를 쓰지 않는다.** `--mono`는 수치·영문 라벨에만.

**제작**: HTML/CSS → Chrome 스크린샷 → WebP (CLAUDE.md 썸네일 절차). 30편이므로
템플릿 1개에 글별 텍스트만 주입하는 방식으로 반복 비용을 낮춘다.

**대상**: GA 상위 30편(§3) ∪ 세로형 2건 = **최대 32편**. 세로형 2건이 상위 30에 이미
들어 있으면 30편이다. 실제 편수는 구현 시 확정한다.

### 4.3 남는 것 (이번 범위 밖으로 명시)

- 레거시 191장은 다크 톤을 유지한다. **두 스타일이 그리드에 공존한다** — 의도된 절충이며,
  상위 30편이 조회의 64.5%라 사용자가 실제로 보는 비중은 새 스타일이 크다
- Unsplash 4건은 외부 의존이 남는다. 상위 30편에 들면 재생성되고, 아니면 다음 라운드
- `tips` 카테고리 7편 · 태그 1144개 사장 · 검색 부재는 **서브프로젝트 2**의 문제다

## 6. 검증

순수 함수가 없는 작업이라 **빌드 + 브라우저 실측**으로 검증한다.
마라톤 개편(`docs/superpowers/design/qa-marathon-discovery.md`)에서 확인했듯 빌드·tsc·lint
통과가 화면 정상을 뜻하지 않는다 — 그때 겹친 글자와 잘린 라벨은 육안으로만 잡혔다.

**좌표 검증 — 네 표면 전부에서 잘림 0**

```js
// naturalRatio == boxRatio 이면 잘림이 없다
[...document.querySelectorAll('article img')].map(i => {
  const b = i.getBoundingClientRect();
  return {
    natural: +(i.naturalWidth / i.naturalHeight).toFixed(3),
    box: +(b.width / b.height).toFixed(3),
    cropPct: +(((i.naturalWidth / i.naturalHeight) / (b.width / b.height) - 1) * 100).toFixed(1),
  };
});
// 기대: cropPct 전부 0.0 (±0.5 이내)
```

**확인 항목**

| 항목 | 기준 |
|---|---|
| 블로그 카드 잘림 | 0% |
| 상세 히어로 잘림 | 0% |
| 홈 에디토리얼 lead 잘림 | 0% |
| 이미지 위 오버레이 | 없음 (배지가 텍스트 블록에 있음) |
| 카테고리 표기 | 킥커 없는 8장 포함 전 카드에 표기 |
| 홈 레이아웃 회귀 | lead 비율 변경 후 홈이 깨지지 않음 (1440/390 스크린샷) |
| 새 썸네일 판독성 | 350px 카드에서 제목·킥커가 읽힘 |
| 비율 이탈 | 재생성 후 세로형 0건 |
| 검증 체인 | `npx tsc --noEmit` → `npm test` → `npm run lint` → `npm run validate` → `set -o pipefail && npm run build` |

**측정 폭**: 1440 / 768 / 390 / 360. 가로 스크롤 0.

## 7. 제약

- **`set -o pipefail`과 함께 검증한다** — `npm run build | tail`이 실패 exit code를 삼킨 이력이 있다
- **`git add`에 파일을 명시한다** — `-A`/`.`/`-a` 금지. `tsconfig.tsbuildinfo`가 딸려 들어간다
- **in-article 광고 슬롯을 건드리지 않는다** — 상세 페이지 본문 분할 로직은 수익 동선이다
- **팔레트 토큰은 실제 `globals.css` 이름을 쓴다** — 미정의 `var()`는 빌드·tsc·lint 어디서도 안 잡힌다
- 이미지 출처는 `public/images/blog/IMAGE_CREDITS.md` 관례를 따른다

## 8. 열린 질문

없음. 재생성 편수(30)는 GA 실측 커버리지에서 뽑았고, 두 스타일 공존은 §4.3에 명시적으로
수용했다.
