# 쎄러데이 — 손기정평화마라톤 8인 도전 기록 페이지

**작성일**: 2026-08-11 (D-96)
**대회일**: 2026-11-15 (2026 손기정평화마라톤 제22회, 임진각)
**URL**: `allrunabout.com/saturday`

---

## 1. 배경과 목적

중학교 친구 8명(운영자 포함)이 토요일마다 모여 뛰던 러닝 크루 **"쎄러데이"** 가
2026 손기정평화마라톤에 출전한다. 풀코스 6명, 10K 2명.

**1순위 목적은 추억 아카이브다.** 8명이 나중에 다시 보려고 만든다.
인스타그램 홍보가 부수 목적이고, SEO·수익은 따라오면 좋은 것으로 취급한다.
이 우선순위를 뒤집으면 페이지가 계산적으로 변해 둘 다 실패한다.

부수 효과로 allrunabout의 구조적 약점(자체 실사용 러닝 데이터 없음)을 메운다.
실제로 뛴 8명의 14주 기록은 랩 수치 해석으로는 만들 수 없는 자산이다.

**1회성 프로젝트다.** 크루는 계속 가더라도 이 페이지는 손기정 2026 한 대회를 다룬다.

## 3. 컨셉 축 — 새벽 소집 (Blue Hour)

> **은유**: 토요일 새벽, 흩어져 살던 여덟이 한 점으로 모인다.

이 축이 히어로부터 결과까지 전 섹션을 지배한다. 색만 바꾸는 것은 실패 경로다.

- **질감** — 찬 공기, 입김, 젖은 아스팔트, 가로등 잔광
- **라이팅** — 감청빛 박명(blue hour) → 지평선 오렌지 → 일출
- **카메라** — 흩어진 8개의 점이 한 프레임으로 수렴 → 출발선 정면 응시

### 서사가 닫히는 방식

```
히어로     어둠 속 여덟 실루엣          #0a1020 (감청)
라인업     하나씩 조명이 켜짐            #0f1830
타임라인   주차가 쌓일수록 밝아짐        #0f1830 → #1e3a5f → #3b6ea5
결과       완전한 일출                   #f0f6ff + 오렌지 액센트
```

**14주 연재가 문자 그대로 해가 뜨는 과정이 된다.** 스크롤을 내리면 D-96의 감청에서
대회 당일 아침 햇빛까지 이어진다. 주차 로그가 추가될수록 배경이 실제로 밝아지므로,
연재가 진행될수록 페이지가 완성돼 간다.

이 축은 사이트의 navy → sky 팔레트와 그대로 접합된다. 다크→라이트 seam이
억지 장치 없이 해결된다.

### 어벤져스 컨셉의 취급

히어로 라인업 형식(정면 응시 8인 나열, 어두운 배경, 실루엣, 능력치 카드)은
저작권 대상이 아니므로 자유롭게 쓴다.

**절대 금지**: 어벤져스 로고, 마블 공식 서체, 마블 캐릭터 이름/얼굴/디자인 차용.
애드센스가 붙은 상업 도메인이므로 회색지대도 피한다.
"어벤져스처럼 보이지만 우리 것" 이 목표다.

## 4. 데이터 유입 — API를 쓰지 않는 이유

Strava·Garmin·Nike Run Club 자동 연동은 **기술이 아니라 라이선스 때문에** 불가하다.
이 결론은 원문 확인으로 검증했다.

**Strava API Policy** (https://www.strava.com/legal/api_policy)
- §2.3 "You may not display or disclose Strava Data related to other users,
  even if such data is publicly viewable on the Strava Platform."
- §5.10 "You may not transfer or disclose Strava Data ... to any third party."
- §5.9 "You may not use Strava Data in any advertisement without Strava's express written consent."
- §3.5 (공식 MCP 서버) "not authorized for ... any commercial or third-party access ...
  outside the developer's own personal use."

→ 8명 데이터를 광고 도메인의 공개 페이지에 올리는 것은 위 세 조항을 동시에 위반한다.
**MCP는 통로일 뿐 권한을 새로 만들지 않는다.**

**Garmin Connect Developer Program** — "available for enterprise use". 개인 대상 아님.
비공식 스크래핑 라이브러리는 친구 8명의 계정 비밀번호를 보관해야 하므로 채택하지 않는다.

**Nike Run Club** — 공식 API 없음(Nike+ 폐기). 비공식 엔드포인트는 ToS 위반.

### 채택하는 경로: 본인이 내보낸 데이터

친구가 자기 계정에서 스스로 내보낸 파일은 API 경로가 아니므로 위 약관의 규율 대상이 아니다.

| 앱 | 방법 |
|---|---|
| 가민 커넥트 | 활동 목록 → CSV 내보내기 |
| 스트라바 | 설정 → 내 계정 → 데이터 내보내기 요청 (activities.csv) |
| 애플 건강 | 건강 앱 → 프로필 → 내보내기 (XML) 또는 HealthFit/RunGap로 CSV |
| 삼성 헬스 | 설정 → 개인 데이터 다운로드 |
| 코로스/폴라/순토 | 각 웹사이트 내보내기 |
| 나이키 런클럽 | 공식 내보내기 없음 → **스크린샷 또는 자가신고** |
| 아무것도 안 씀 | 자가신고 ("주 3번, 한 번에 8km쯤") |

**포맷이 8개 다 달라도 무방하다.** 8개 파일은 수작업 정규화가 가능한 양이다.
친구들에게는 "쓰는 앱에서 뽑을 수 있는 거 아무거나"로 요청한다.

### 수집 주기

| | 언제 | 무엇 | 부담 |
|---|---|---|---|
| 내보내기 | 지금 1회 + 대회 후 1회 | 전체 이력 → 베이스라인/최종 | 친구당 2번, 각 3분 |
| 카톡 한 줄 | 매주 | "이번주 몇 km + 한마디" | 운영자 주 10분 |

내보내기를 매주 요구하면 3주차에 응답이 끊긴다. **딱 두 번**으로 고정한다.

## 5. 결측 데이터 설계 — CLASSIFIED

**데이터를 필수로 만들지 않는다.** 8명 중 2명이 안 주면 카드가 비고, 운영자가 독촉하게 되고,
재미로 하던 것이 숙제가 된다.

카드는 데이터 유무에 따라 두 상태를 가진다.

```
[stats 있음]                  [stats 없음]
코드네임                       코드네임
실명 · 풀코스                  실명 · 10K
⬡ 레이더 차트 (실측)           ▓▓ CLASSIFIED — 기록 미공개
목표 4:30:00                   목표 완주
```

**가려진 카드가 미완성으로 보이면 안 된다.** "정보 없음"이라는 설정이 되어야 한다.
나중에 데이터가 들어오면 **해금(unlock)** 연출이 되고, 인스타에 "OO 능력치 공개"로
한 편이 나온다. 독촉 없이 참여를 유도하는 구조다.

**8명 중 3명만 데이터를 줘도 페이지는 완성 상태다.**

### 친구에게 실제로 요구하는 최소 항목

1. **코드네임** (기존 별명이면 됨)
2. **종목** — 풀 / 10K (이미 확정)
3. **목표** — "4시간 30분" 또는 "완주"

이 셋이 필수의 전부다. 주간 거리·내보내기 파일·사진은 전부 보너스다.

## 6. 데이터 모델

`src/lib/data/challenge/saturday.ts` 단일 파일.

```ts
export interface CrewStats {
  source: '가민' | '스트라바' | '애플' | '삼성' | '기타' | '자가신고';
  asOf: string;          // 'YYYY-MM-DD' 기준일
  weeklyKm: number;      // 최근 4주 평균 주간 거리
  longestKm: number;     // 최장 단일 거리
  avgPaceSec: number;    // 초/km
  runsPerWeek: number;   // 최근 4주 평균 주 러닝 횟수
  totalKm?: number;      // 누적 (있으면)
}

export interface CrewMember {
  id: string;            // 'm1' — 이미지·로그 참조용 안정 키. 변경 금지
  codeName: string;      // 크게 표시
  realName: string;      // 작게 표시. 원치 않으면 '' (렌더 생략)
  distance: '풀코스' | '10K';
  goal: string;          // '4:30:00' | '완주'
  photo?: string;        // 없으면 실루엣 자동 대체
  baseline?: CrewStats;  // 없으면 CLASSIFIED
  final?: CrewStats;     // 대회 후 채움. 있으면 레이더 겹쳐 그리기
}

export interface WeekEntry {
  memberId: string;
  km?: number;
  note?: string;         // "롱런 25km 목표였는데 18km에서 무릎 나감 ㅋㅋ"
}

export interface WeekLog {
  week: number;          // 1..14
  dday: number;          // 96, 89, ...
  dateLabel: string;     // '08.11 – 08.17'
  headline?: string;     // 그 주 한 줄 요약 (운영자 작성)
  entries: WeekEntry[];
}

// 대회 후에만 채운다. 없으면 결과 섹션 자체가 렌더되지 않는다 (7-4)
export interface RaceResult {
  heroLine: string;      // 히어로 교체 문구. 예: '여덟 명 전원 완주'
  finishers: {
    memberId: string;
    finishTime?: string; // '4:28:11' — 미완주 시 생략
    note?: string;       // 완주 후 한마디
    photo?: string;
  }[];
}
```

**표기 방식을 사람별 필드로 둔 것이 핵심이다.** 한 명이 "사진 빼줘", "별명으로 바꿔줘"
라고 해도 그 사람 한 줄만 고치면 끝난다. 8명의 마음이 14주 동안 바뀔 수 있으므로
유연함을 구조에 심는다.

### 레이더 차트 정규화 상수 (고정)

값이 흔들리지 않도록 문서에 못박는다. 4축 모두 0–100으로 정규화한다.

| 축 | 소스 | 매핑 |
|---|---|---|
| 주력 | `weeklyKm` | 0–60km → 0–100 (60 초과는 100) |
| 지구력 | `longestKm` | 0–42.195km → 0–100 |
| 스피드 | `avgPaceSec` | 420초(7:00/km) → 0, 300초(5:00/km) → 100, 선형 보간 |
| 꾸준함 | `runsPerWeek` | 0–5회 → 0–100 (5 초과는 100) |

차트는 Recharts `RadarChart` 사용 (이미 스택에 있음).
`baseline`과 `final`이 모두 있으면 두 폴리곤을 겹쳐 그려 14주 성장을 보여준다.
이것이 프로젝트의 마지막 장면이며 인스타 최종 카드로도 나간다.

## 7. 화면 설계 (모바일 우선, 기준 390px)

단일 페이지 4층. 개인 상세 URL은 만들지 않는다.

### 7-1. 히어로

```
        [감청 그라데이션 · 상단 어두움]

              쎄 러 데 이            ← 한글 워드마크, 크게
                                       (러닝 크루 대부분 영문이라 역으로 눈에 띔)
   토요일마다 모여 뛰던 중학교 친구 여덟이,
        42.195km 앞에 섰다.

   2026.11.15 · 손기정평화마라톤 · 임진각
              D-96

        [여덟 개의 실루엣이 하나씩 페이드인]
             ↓ 기록 보기 (상시 노출)
```

- **h1은 실텍스트로 렌더한다.** `sr-only` 하나로 때우지 않는다 (크롤러·접근성)
- **액션 앵커를 첫 화면에 상시 노출한다.** 스크롤 끝에서 CTA가 나오는 구성 금지
- 카피 뒤에 radial 스크림을 상시 깔아 배경 대비와 무관하게 가독성 확보
- D-day는 빌드 시각 기준 계산 (SSG이므로 배포마다 갱신)

### 7-2. 라인업

모바일 **2열 그리드 × 4행**. 카드 탭 시 그 자리에서 인라인 확장(아코디언).
별도 URL·모달 없음.

카드 구성: 사진 또는 실루엣 / 코드네임(크게) / 실명·종목(작게) / 레이더 또는 CLASSIFIED / 목표

확장 시 추가: 베이스라인 수치 원값, 최근 한마디, 데이터 출처 표기

### 7-3. 타임라인

세로 스택. 최신 주차가 위. 각 주차 블록:

```
D-88 · 2주차                    08.18 – 08.24
"첫 롱런 주간. 셋이 20km를 넘겼다."        ← headline (운영자)

  코드네임   32km   "무릎이 슬슬 신호를 보냄"
  코드네임   18km
  코드네임    —     (기록 없음 → 빈칸, 강조하지 않음)
  ...
```

**배경색이 주차에 따라 밝아진다.** 1주차는 감청, 마지막 주차는 새벽빛.
그라데이션은 주차 인덱스로 계산하며, 주차가 추가되면 자동으로 재분배된다.

기록 없는 사람은 `—` 로 조용히 처리한다. 결측을 시각적으로 벌하지 않는다.

### 7-4. 결과 (11/15 이후)

**렌더 조건**: 데이터 파일의 `raceResult` 가 존재할 때만 렌더한다.
날짜 비교가 아니라 데이터 유무로 판단한다 — 대회 당일에 결과가 즉시 나오지 않으므로.
그때까지 이 섹션은 DOM에 존재하지 않는다 (빈 섹션 노출 금지).

채워지면: 8명 기록 / 완주 사진 / 각자 한마디 / **베이스라인 vs 최종 레이더 겹치기**.

히어로 문구는 이 시점에 "8명 전원 완주" 류로 교체한다 (데이터 파일 상수).

```

소개   토요일마다 모여 뛰는 여덟 명
       2026.11.15 손기정평화마라톤 · 풀 6 / 10K 2

```

기존 `scripts/thumbnail/` 파이프라인을 확장해 **동일 데이터로 인스타 카드(1080×1080)를
생성**한다. 주간 운영이 한 경로로 합쳐진다:

```
카톡 수집 → 데이터 파일 한 줄 추가 → 페이지 갱신 + 인스타 카드 자동 생성
```

주 1회 10분에 웹·인스타가 동시에 돈다.

**OG 이미지**(1200×630)는 8인 라인업 조합으로 만든다. 인스타 스토리 링크에서
썸네일이 제대로 뜨는지가 공유율을 크게 좌우한다.

콘텐츠 축: 주간 카드 / D-day 카운트다운 / 능력치 해금 / 완주 후 최종 비교.
릴스는 8명이 각자 찍은 것을 모은다.

## 9. 성능·구현 제약

프로스펙스 데모(미팅용 단일 HTML, 588KB, 외부요청 0)와 달리 **이것은 프로덕션 페이지다.**
리포에 CI 페이로드 가드가 있고, 인스타 인앱 브라우저에서 열린다.

- **시네마틱은 히어로에 집중한다.** 나머지 섹션은 정적 + CSS 트랜지션
- **canvas 파티클을 쓰지 않는다.** 실루엣·그라데이션은 인라인 SVG + CSS로 구현
  (모바일 배터리·발열·저가 단말 대응)
- 이 페이지 클라이언트 JS **≤ 120KB**, 모바일 4G LCP **≤ 2.5s** 목표
- 라우트 그룹이 분리돼 있으므로 다른 페이지 번들에 영향 없음
- `transform`/`opacity`만 애니메이트. 단일 RAF, IntersectionObserver는 1회 후 unobserve
- `prefers-reduced-motion` 시 **완전 정적**. 배경 애니메이션도 멈춘다
- 한글 안전 폰트 스택: Pretendard → Apple SD Gothic Neo → Malgun Gothic
  (사이트에 이미 Pretendard 로드됨)
- 모바일 100vh 문제 → `dvh` 사용
- 터치 타겟 최소 44px

## 10. 개인정보·법적

- **원본 내보내기 파일은 리포에 커밋하지 않는다.** GPS에 집 주소, 심박에 건강정보가 들어 있다.
  `.gitignore` 등록 후 로컬 보관. **가공된 집계치(`CrewStats`)만 커밋한다.**
- GPS 경로를 시각화하지 않는다 (컨셉 C를 탈락시킨 이유이기도 하다)
- 실명은 `realName: ''` 로 언제든 제거 가능. 사진은 `photo` 미지정 시 실루엣
- 8명 동의는 획득 완료. 개별 이탈 요청은 해당 멤버 필드만 수정해 반영한다
- 마블 IP 자산 미사용 (3절)

## 12. 구현 범위 분할

이 스펙은 **1단계까지**를 단일 구현 계획으로 다룬다. 2·3단계는 별도 계획으로 뺀다.

| 단계 | 범위 | 시점 |
|---|---|---|
| **1** | 라우트 그룹 · 데이터 모델 · 히어로 · 라인업 · 타임라인 · OG 이미지 | 지금 (D-96) |
| 2 | 인스타 카드 생성 (`scripts/thumbnail/` 확장) | 1단계 배포 후 |
| 3 | 결과 섹션 · 레이더 겹치기 | 11/15 이후 |

1단계만으로 페이지는 공개 가능한 완성 상태다 — 결과 섹션은 데이터가 없으면
애초에 렌더되지 않고, 인스타 카드는 웹 페이지와 독립적이다.

## 13. 검증 방법

플레이북 7단계를 따른다. **자동 수치만으로 완료 처리하지 않는다.**

- Chrome DevTools로 5프레임 스크린샷: 진입 시점 / 실루엣 전체 노출 / 카피 /
  타임라인 밝기 전환부 / reduced-motion
- **모바일 검증은 `emulate`가 플래키하므로 `window.open`으로 390px 실창을 띄운다**
- 데이터 결측 시나리오 육안 확인: stats 0명 / 3명 / 8명
- `npm run build` 통과 및 페이로드 가드 통과
