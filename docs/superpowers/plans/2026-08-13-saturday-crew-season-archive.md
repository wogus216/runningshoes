# 쎄러데이 시즌형 아카이브 — 후속 구현 계획

**작성일:** 2026-08-13

**브랜치:** `feat/saturday-crew`

**정본 스펙:** `docs/superpowers/specs/2026-08-11-saturday-crew-design.md`

## 목표

현재 `/saturday` 골격과 8인 placeholder 데이터를 최종 7인 구성으로 바로잡고, `MISSION 00` 티저 사이트를 먼저 공개한다. 이후 로컬 미션 폴더 하나가 웹 앨범과 Remotion 릴스의 공통 입력이 되도록 확장한다.

## 전제

- 로스터: 재춘 · 감자 · 형가 · 기태 · 지자 · 남길 · 광묵
- 참가 거리: 재춘·감자·형가·기태·지자·남길 풀코스 6명 + 광묵 10K 1명
- 공개 방식: 코드네임과 사진, 실명 미노출
- 톤: 어두운 미션 입장 → 밝은 스포츠 매거진 앨범 → 어두운 다음 미션 예고
- 웹 앨범: 공식 크루 러닝과 중요 훈련만 기록
- 사진 수집: 단톡방 → 운영자 선별 → 로컬 폴더
- 릴스: 사진만으로 완성, 영상 클립은 선택

## Phase 1 — 현재 상태 정합성 복구

### 작업

- `SATURDAY_CREW`를 7명으로 변경하고 실제 코드네임 적용
- 풀코스 6명과 10K 1명 매핑 확정
- metadata의 `여덟 명`, `토요일마다`, `10K 2명` 문구 제거
- 기존 8인 전제 테스트와 OG 스크립트 점검
- 초기 페이지에 남아 있는 Blue Hour 전용 상수는 MISSION 00에 필요한 것만 유지

### 확인

- 저장소 전체에서 `여덟`, `8인`, `MEMBER 8`, `10K 2`가 실행 코드에 남지 않음
- `npm test`
- `npm run build`

## Phase 2 — MISSION 00 웹 티저

### 작업

- 7개의 서로 다른 자체 SVG 실루엣 제작
- `MISSION HERO`에 대표 훅·시즌 표제·개인에서 팀으로 확장되는 전환 적용
- `CREW REVEAL`에 코드네임·거리·강점·웃긴 약점을 수용하도록 타입 확장
- `RACE TARGET`에 `FULL × 6 · 10K × 1`, 대회일, D-day, `TO BE CONTINUED` 적용
- 첫 공개는 위 세 문단만 구현하고 사진 앨범·누적 통계는 실제 기록이 생길 때 추가
- Race Target 하단에 Instagram CTA와 공유 메타데이터 적용

### 확인

- 390px, 768px, 1440px 스크린샷 검토
- 7개 실루엣이 서로 구분되고 한 명도 강조/축소되지 않음
- reduced motion에서도 모든 코드네임과 훅이 즉시 보임
- 모바일 인스타 인앱 브라우저에 준하는 느린 네트워크에서 LCP 확인
- `npm run build`

## Phase 3 — 로컬 시즌·미션 콘텐츠 파이프라인

### 작업

- `content/saturday/season-01/mission-NN/` 구조 생성
- `episode.json` 스키마와 Zod 검증 추가
- 폴더를 스캔해 번호순 에피소드와 최신 에피소드를 반환하는 서버 전용 로더 작성
- 대표 사진, 갤러리, 캡션, 사건, 이번 주의 인물 렌더링
- 누적 거리와 함께 달린 횟수를 에피소드 데이터에서 계산
- 잘못된 사진 경로, 중복 미션 번호, 필수값 누락을 빌드 전에 실패시키는 검증 스크립트 추가

### 확인

- 빈 시즌, MISSION 00만 존재, 사진 1장, 사진 10장, 선택 영상 포함 시나리오 테스트
- 최신 미션은 상단, 전체 앨범은 오름차순으로 렌더됨
- 사진의 고유 비율이 모바일과 데스크톱에서 유지됨
- `npm test`
- `npm run build`

## Phase 4 — Remotion 공통 입력과 MISSION 00 티저

### 작업

- Remotion 프로젝트 구조와 1080×1920 composition 추가
- 웹 로더와 같은 `episode.json` 데이터를 읽는 어댑터 작성
- `Mission00Teaser` 12–15초 composition 구현
- 대표 훅 → 7인 코드네임 → 거리 구성 → 시즌 표제 → 사이트 주소 순서로 전개
- 사진만으로 완성되는 `WeeklyMissionReel` 템플릿 구현
- 영상 클립은 존재할 때만 삽입하고 없으면 타이밍이 무너지지 않게 설계
- 렌더 명령과 산출물 경로 문서화

### 확인

- 1080×1920 still로 타이포 안전 영역 확인
- 음소거 상태에서도 내용을 이해할 수 있음
- 15초 티저와 20–30초 정규 릴스가 동일 데이터로 렌더됨
- 한글 폰트 로딩 완료 후 렌더 시작
- Remotion 렌더 테스트
- `npm run build`

## Phase 5 — 실제 사진 전환과 시즌 종료

### 작업

- 첫 공식 단체사진을 실루엣 히어로와 교체
- 실제 강점·웃긴 약점 입력
- 레이스 결과와 완주 사진 추가
- `MISSION COMPLETE`와 다음 대회 teaser 데이터 구조 추가
- 다음 시즌 생성 시 시즌 1 URL과 콘텐츠가 변하지 않도록 보존

### 확인

- 시즌 1 전체를 처음부터 시간순으로 읽을 수 있음
- 상단 최신 미션과 본문 시간순 앨범이 충돌하지 않음
- 다음 대회 미정/확정 두 상태 모두 자연스럽게 렌더됨
- `npm test`
- `npm run build`
