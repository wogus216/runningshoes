# 러닝카드 개인화 분석 개선 — 2026-10-12

## 합의한 목적

주 2~4회 달리는 취미 러너가 자신의 스타일을 이해하고 저장·공유하고 싶어지는 분석지. 입력은 기존 항목을 쓰고, 기록·목표·인물을 연결한다. 신화 표현은 칭호·신탁에 두고 분석은 구체적인 존댓말로 쓴다.

## 구현

- 지난 28일의 소개 → 인물과 닮은 기록 특성·목표 → 세 점수의 해석과 펼쳐보는 계산 근거 → 강점과 균형 → 내 스타일을 살리는 행동.
- `explain.ts`에서 실제 집계와 목표로 문구를 고른다. 요일 유무에 따른 규칙성 상수를 강점의 증거로 쓰지 않는다. 유형과 점수 계산 자체는 기존 엔진을 사용한다.
- 목표가 건강·재미·습관이면 강한 훈련이 적다는 이유만으로 결함을 만들지 않는다. 대회 목표 기록이 입력되면 판정 엔진의 대회·기록 목적 혼합도 설명한다.
- 한 번의 러닝, 요일 없음, 연속 요일, 강한 훈련 ‘6회 이상’, 목표 페이스 계산 범위 밖을 따로 설명한다. 집계만으로 규칙성·최근 향상·실제 회복·완주 가능성을 단정하지 않는다.
- 공유 1장은 메달 표지, 2장은 개인 소개·세 점수 해석·강점과 균형의 짧은 요약. 본문을 통째 축소하지 않고 본문 36px와 가변 단락 간격으로 배치한다. 메달은 소개와 겹치지 않게 상단에 둔다.
- 기록 숨김은 메달의 숫자·요일뿐 아니라 소개의 원시 수치도 숨긴다. 해석과 인물·세 점수는 남긴다. 공유 링크는 기존 인물·점수 형식을 유지하고 상세 해석은 이미지로 전한다는 안내를 붙인다.
- 새 API·저장소·외부 생성 호출·의존성은 필요 없다. 기존 결과 보기·표지 저장·2장 저장·공유 이벤트를 계속 사용한다.

## 검증

- `npm test`: 33개 파일, 395개 테스트 통과. 합성 러너 10,000명의 필수 설명·점수 일치·숨김 숫자 누출·낮은 회복 여유에서 강도 증가 권유 금지를 포함한다.
- `npm run build`: 정적 페이지 1,083개 생성. 기존 다른 페이지의 img 권고 경고만 존재.
- `analysis.mjs`: 36인물 × 5목표 × 6경계 입력 × 피드/스토리 × 보임/숨김 = 4,320장. 텍스트 가로 잘림·하단 설명 겹침 검사 통과. 본문은 36px, 가장 작은 보조 라벨은 26px.
- `drive.mjs`: WebGL과 2D 대체 경로에서 실제 입력·분석 열기·계산 근거 열기/닫기·2장 저장·숫자 숨기기·설정 변경 후 다시 열기·PNG 파일 공유·은/황동 표지·다시 하기 검증. 2D 경로는 실제 모바일 뷰포트 390px와 320px 가로 넘침도 확인.
- 검수 산출물: `/tmp/running-card-rich-analysis-qa-v2`, `/tmp/running-card-rich-e2e`, `/tmp/running-card-rich-flat`. 재현 명령은 `docs/running-card-harness/README.md`.
