## 3. 판단이 필요한 것

1. **A절 리뷰 수집 절차(Chrome DevTools로 BITR·DOR 페이지 읽기) 존치 여부**
   - 선택지 ⓐ 그대로 둠(이번 처리 — 경고 블록만 추가) ⓑ 절 제목을 "외부 리뷰 참고 자료 수집"으로 바꾸고 `evaluate_script` 예시 축소 ⓒ 삭제.
   - 근거: 실명 출처 인용(본문 근거 위계 ②)과 RunRepeat 미게시 신상 스펙 확인에 여전히 쓰이는 절차라 지우지 않았다. 다만 제목이 "리뷰 데이터 수집"이라 "후기 수집"으로 읽힐 여지가 있다.
2. **`scripts/validate.ts` 7번의 우회 구멍** (코드 미변경, 맡은 범위 밖)
   - `SOURCED = /에디터|분석|리뷰어|Believe|.../i`에 걸리는 `userType`은 7번 검사를 통째로 건너뛴다. 옛 예시(`'Believe in the Run 리뷰어'`, `rating: 73`)는 **현재 validate를 통과한다.** 이번 문서 정정으로 예시는 없어졌지만, 같은 형태로 쓰면 검증이 막지 못한다.
   - 선택지: ⓐ 그대로 둠 ⓑ `userType`이 `'예상 적합 — '`로 시작하지 않으면 경고 ⓒ shoes의 reviews에서 rating을 전면 금지.
3. **C절 researcher 템플릿의 WebSearch 사용 안내**("WebFetch 우선, 실패 시 WebSearch", 한국 가격은 "WebSearch로 네이버 쇼핑 공식가 + 블로그 교차 확인")
   - 클라우드 공통 규칙 1(WebSearch 금지·집계 블로그 수치 금지)과 어긋난다. 이번 작업 범위(reviews 예시)가 아니라 고치지 않았다. 로컬 세션용 안내로 둘지, 규칙에 맞춰 고칠지 결정이 필요하다.
4. **C절 「5. 리뷰 작성 원칙 (추정 기반일 때)」·매핑의 `stability: 카테고리 + 리뷰 기반 판단`**
   - "리뷰"가 본문 서술·외부 리뷰를 뜻해 `reviews` 필드 안내는 아니라고 보고 건드리지 않았다. stability 수치화는 문서상 "미정, 건드리지 말 것"이다.
